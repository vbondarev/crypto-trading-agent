# Crypto Trading Agent v2

Агент анализирует рынок и выбранную монету, предлагает стратегию, проверяет риск и, когда данные это позволяют, готовит черновик настроек для Veles или GinArea.

1. **Анализ рынка.** Оценивает общий фон и факторы, влияющие на монету. Указывает источники, время данных и пробелы.
2. **Технический анализ монеты.** Сам запрашивает публичные свечи Bybit и по закрытым свечам разбирает тренд, ключевые уровни и волатильность.
3. **Выбор стратегии.** Обосновывает `LONG`, `SHORT` или `WAIT` и описывает условия входа, выхода и отмены сценария.
4. **Проверка риска.** Сверяет сценарий с бюджетом и лимитами с учётом доступных данных о портфеле. Указывает, какие проверки ещё нужны.
5. **Черновик настроек бота.** Сопоставляет параметры с полями и единицами выбранной платформы. При `WAIT` или подтверждённом нарушении лимита объясняет причину и условия пересмотра решения.

Агент получает свежие публичные данные Bybit при локальном запуске с доступом к `api.bybit.com`. В Codex Cloud используй сохранённый рыночный срез. Режим выпуска — `NO_TRADE_READY`. Подключение реального счёта, размещение ордеров и запуск ботов требуют отдельной приёмки.

## Как начать

Открой рабочую версию `vbondarev/crypto-trading-agent`, в которой активен v2, и выбери маршрут по источнику данных.

- **Свежие данные Bybit.** Открой локальную копию проекта в Codex. Из этого сеанса агент запросит публичные данные через `api.bybit.com`.
- **Сохранённый срез.** Открой проект в Codex Cloud и приложи срез с указанием биржи, рынка, даты, времени и часового пояса. Агент выполнит анализ на момент среза. В проверенном облачном окружении запросы к Bybit возвращали HTTP `403`.

Укажи монету, рынок и горизонт. Для черновика добавь платформу, режим бота и тестовый бюджет, если он известен.

## Пример запроса

Пример ниже рассчитан на локальный запуск. В Codex Cloud замени предложение о получении данных на «Используй приложенный сохранённый срез и оцени сценарий на 1–3 дня от момента среза».

> Прочитай корневой `AGENTS.md` из версии проекта, открытой в этом сеансе. Убедись, что в ней активен маршрут v2. Оцени HYPEUSDT на Bybit USDT Perpetual на ближайшие 1–3 дня. Сам получи публичные данные Bybit для текущего анализа.
>
> 1. Опиши рыночный фон и укажи источники и время данных.
> 2. По закрытым свечам HYPEUSDT покажи тренд, ключевые уровни и волатильность. Если свечей недостаточно, укажи, каких данных не хватает.
> 3. Предложи `LONG`, `SHORT` или `WAIT`. Объясни, при каких условиях стоит входить, выходить или отменить сценарий.
> 4. Проверь сценарий по доступным данным о бюджете, портфеле и лимитах риска. Укажи, что удалось подтвердить и каких данных не хватает.
> 5. Если стратегия допускает вход и данные позволяют, подготовь черновик для Veles SIMPLE. Для каждого параметра укажи поле, единицу измерения и основание. При `WAIT` или нарушении лимита объясни, почему вход не подходит и что изменило бы вывод.

Для знакомства с форматом можно открыть [синтетический пример HYPEUSDT](tests/v2/fixtures/incomplete-hype.v1.json) и попросить агента объяснить, почему анализ закончился решением `WAIT`.

Не публикуй в репозитории API-ключи, пароли, снимки счёта и реальные торговые отчёты.

Для разработки и проверок v2 используй Python. Команды выполняются из корня репозитория.

```powershell
python -m pip install -r tests/v2/requirements.txt
python tests/v2/workflow_smoke.py
python tests/v2/pilots/test_stage09_portfolio_risk.py
```
