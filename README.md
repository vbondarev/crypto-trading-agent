# Crypto Trading Agent

Агент анализирует рынок и выбранную монету, предлагает стратегию, проверяет риск и, когда данные это позволяют, готовит черновик настроек для Veles или GinArea.

1. **Анализ рынка.** Оценивает общий фон и факторы, влияющие на монету. Указывает источники, время данных и пробелы.
2. **Технический анализ монеты.** Запрашивает публичные свечи Bybit, рассчитывает EMA20/50, RSI(14), ATR(14) и RVOL штатным Python-калькулятором и разбирает тренд и ключевые уровни по закрытым свечам.
3. **Выбор стратегии.** Обосновывает `LONG`, `SHORT` или `WAIT` и описывает условия входа, выхода и отмены сценария.
4. **Проверка риска.** Сверяет сценарий с бюджетом и лимитами с учётом доступных данных о портфеле. Указывает, какие проверки ещё нужны.
5. **Черновик настроек бота.** Сопоставляет параметры с полями и единицами выбранной платформы. При `WAIT` или подтверждённом нарушении лимита объясняет причину и условия пересмотра решения.

Агент получает свежие публичные данные Bybit при локальном запуске с доступом к `api.bybit.com`. В Codex Cloud используй сохранённый рыночный срез. Режим выпуска — `NO_TRADE_READY`. Подключение реального счёта, размещение ордеров и запуск ботов требуют отдельной приёмки.

## Как начать

Открой локальную копию `vbondarev/crypto-trading-agent` в Codex и начни чат в этом проекте. Агент использует текущий `HEAD`, если ты не указал другой коммит, тег или ветку, и получает свежие публичные данные с `api.bybit.com` без авторизации.

Для анализа сохранённого среза открой в Codex Cloud версию проекта, в которой есть [эталонный промт](docs/prompts/reference-market-analysis.md) и [штатный калькулятор](tools/technical_indicators.py). Приложи данные с указанием биржи, рынка, даты, времени и часового пояса. В сообщении попроси использовать приложенный срез вместо запроса живых котировок и отсчитать горизонт от времени среза. В проверенном облачном окружении публичный API Bybit возвращал HTTP `403`.

## Пример запуска

Отправь в чат сообщение ниже. Агент прочитает эталонный промт из проекта и подставит параметры из сообщения. Суммы в примере условные.

```text
Выполни промт из `docs/prompts/reference-market-analysis.md` в открытом проекте.
Для этого запуска используй следующие параметры:

Целевой тикер — HYPEUSDT.
Рынок — Bybit USDT Perpetual.
Горизонт — 1–3 дня.
Платформа для черновика — AUTO.
Режим бота — НЕ_ЗАДАН.
Депозит — 150 USDT, бюджет на этого бота.
Доступная маржа Bybit — 75 USDT.
Полного снимка фьючерсного портфеля нет.
```

- **Платформа и режим.** При `AUTO` агент сравнит Veles и GinArea и объяснит предлагаемую связку «платформа + режим». Если платформа уже выбрана, укажи `VELES` или `GINAREA`. При `НЕ_ЗАДАН` агент предложит подходящий режим. Конкретные значения перечислены в [шапке промта](docs/prompts/reference-market-analysis.md#параметры-анализа).
- **Депозит и маржа.** Депозит по умолчанию означает бюджет бота. Если передаёшь баланс всего счёта, укажи это явно. Доступную маржу передай с валютой и, если известно, временем наблюдения и часовым поясом. Неизвестные значения можно оставить `НЕ_ЗАДАН`. При обоснованном входе меньшая из сопоставимых сумм по одному счёту и обеспечению служит предварительным потолком бюджета.
- **Итог анализа.** Агент отдельно выводит рыночное решение, статус проверки риска и статус черновика. Без снимка всего счёта риск портфеля остаётся `NOT_EVALUABLE`. При `WAIT` черновик получает `NOT_RECOMMENDED`, числовые настройки не формируются.

Для знакомства с форматом можно открыть [синтетический пример HYPEUSDT](tests/v2/fixtures/incomplete-hype.v1.json) и попросить агента объяснить решение `WAIT`. Личные суммы передавай в чате. API-ключи, пароли, снимки счёта и реальные торговые отчёты храни вне репозитория.

## Разработка и испытания

Для воспроизводимых проверок используй **Python 3.12**. Команды выполняются из корня репозитория.

### Установка Python

**Windows (PowerShell).** Установи Python Install Manager, затем открой новое окно PowerShell. Если Python 3.12 уже установлен и команда проверки работает, переходи к созданию виртуального окружения. [Загрузка для Windows](https://www.python.org/downloads/windows/) · [Справка Python для Windows](https://docs.python.org/3/using/windows.html)

```powershell
py install 3.12
py -3.12 --version
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Если PowerShell блокирует активацию, в командах установки зависимостей и запуска тестов ниже используй `.\.venv\Scripts\python.exe` вместо `python`.

**macOS.** Выбери выпуск Python 3.12 с установщиком `.pkg` на python.org и запусти его. Открой новое окно Terminal, проверь версию и создай окружение. [Загрузка для macOS](https://www.python.org/downloads/macos/) · [Справка Python для macOS](https://docs.python.org/3/using/mac.html)

```bash
python3 --version
python3 -m venv .venv
source .venv/bin/activate
```

Если `python3` указывает на другую установленную версию, для воспроизведения проверок создай окружение через `python3.12 -m venv .venv`.

**Linux.** На Ubuntu и Debian установи Python и поддержку виртуальных окружений через APT. На Fedora Python обычно уже установлен. При необходимости поставь его через DNF. [Руководство Ubuntu](https://documentation.ubuntu.com/ubuntu-for-developers/tutorials/python-use/) · [Руководство Fedora](https://developer.fedoraproject.org/tech/languages/python/python-installation.html)

```bash
# Ubuntu и Debian
sudo apt update
sudo apt install python3 python3-venv
```

```bash
# Fedora, если Python отсутствует
sudo dnf install python3
```

Затем проверь версию Python и создай окружение. Если версия по умолчанию отличается от 3.12, для воспроизведения проверок используй `python3.12 -m venv .venv`, если эта версия уже установлена. На Fedora её можно добавить командой `sudo dnf install python3.12`, если пакет доступен для твоего выпуска.

```bash
python3 --version
python3 -m venv .venv
source .venv/bin/activate
```
