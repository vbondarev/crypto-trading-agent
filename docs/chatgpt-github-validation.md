# Проверка работы ChatGPT с инструкциями GitHub

**Статус:** базовые проверки пройдены; проверка актуальности после изменения файла оставлена дополнительным регрессионным тестом. Результаты реального теста находятся в истории ChatGPT.

## Цель

Подтвердить, что в пользовательском диалоге ChatGPT может получать актуальные файлы репозитория и применять их по явному запросу. Наличие GitHub-подключения не означает автоматического применения `AGENTS.md` или `SKILL.md`.

## Проверки

1. Открыть и прочитать `README.md`, `AGENTS.md` и `docs/development-roadmap.md` из заданного репозитория.
2. Назвать существующие файлы и отличить их от документов, которые только планируются.
3. По запросу перечислить текущие ограничения MVP без вымышленных функций.
4. Продемонстрировать использование приоритетов инструкций и правила не выдумывать недостающие данные.
5. Проверить, что при повторном открытии файла агент видит актуальную версию после изменения в GitHub.

## Приёмка

- Каждый результат подтверждён фактическим чтением файла по ссылке или через GitHub-подключение.
- Если файл отсутствует или доступ закрыт, агент сообщает об ограничении.
- Выбран рабочий стартовый пользовательский промпт для загрузки инструкций.
- Результаты проверки фиксируются в истории ChatGPT (не в Git).

## Запуск проверки

Пользовательский тестовый запрос:

> Открой репозиторий `vbondarev/crypto-trading-agent`. Прочитай `AGENTS.md`, `README.md` и `docs/development-roadmap.md`. Кратко объясни назначение проекта, текущий этап, границы MVP и какие документы реально существуют. Не считай файлы доступными, пока не прочитал их.

## Результаты базовой проверки

- Пройден тест чтения `AGENTS.md`, `README.md` и `docs/development-roadmap.md` из `main` через GitHub с разграничением существующих и планируемых документов.
- Пройден тест применения базовых инструкций: модель отказалась считать конфигурацию Veles готовой без данных о портфеле и проверки риска.
- Пройден тест чтения `docs/chatgpt-github-validation.md` в `feature/initial-agent-mvp` и подтверждения его отсутствия в `main`.
- Проверка получения обновлённого файла после нового коммита **не проводилась**: она остаётся необязательным регрессионным тестом.
- Стартовый способ загрузки — в новом чате явно указывать репозиторий и ветку, запрашивать повторное чтение `AGENTS.md` и связанных инструкций перед новым сценарием. Автоматическая загрузка не доказана.

**Итог:** этап 02 принят в рамках базового объёма; можно переходить к формализации требований (этап 03).
