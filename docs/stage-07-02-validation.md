**Формат проверен по** [Agent Skills Specification](https://agentskills.io/specification) (текст просмотрен 19.10.2026): SKILL.md с YAML `name`, `description`, Markdown body; относительные пути от корня skill; `references`/scripts необязательны. В данной реализации **не** запускался `skills-ref validate`, не проводился отдельный промышленный YAML-парсинг, не доказано реальное автоматическое обнаружение Skill в текущем ChatGPT/Codex/Responses API. Метаданные проверены лексически, по фактическому содержимому файла из GitHub, со специально упрощённым предикатом. Это не равно full schema validation.

### 1.1. Поддерживаемые границы задачи

| Режим | Проверяемые данные | Что Skill НЕ делает |
|---|---|---|
| **R1 — обзор** | Совместимость источника и рынка, явные даты, Last/Mark/Index, применимые 15 минут и контекст | Не требует полного T02 или P02 для объяснения/достаточного общего обзора |
| **R2 — предварительный сценарий** | 5-минутная текущая цена для intraday; последняя **закрытая** OHLCV свеча и достаточная история; конфликты/ограничения | Не объявляет предварительные уровни готовой торговой стратегией или `READY` |
| **R3 — финальная валидация** | Mark ≤2 минут; **полный** T02 ≤5 минут плюс отсутствие событий; реальная P02 выбранной платформы; спецификация инструмента ≤24 часов; риск и бот | Не подменяет Risk/Portfolio/Veles/GinArea, не вычисляет гарантированную Cross ликвидацию/Short loss и не присваивает `READY` |

Прочие временные правила: стакан/поток (если требуется, ориентир ≤30 секунд), OI (≤15 минут если существенно), funding (для R3 при существенности ≤10 минут; для R1/R2 ≤30 минут), инструментальный справочник R1/R2 ≤7 суток только для контекста. Реальный режим AD-009 может требовать **меньший** TTL; устаревшая отметка не «омолаживается» перепубликацией.

### 1.2. Проверка provenance

Skill обязывает различать `observed_at`, `response_time`, `retrieved_at`, `snapshot_at`, `published_at`, `market_startTime`; отдельно `exchange / symbol / category / priceKind / units / interval`. Чужой Binance Spot Last не становится Bybit USDT Perpetual Mark. HTTP 403 фиксируется для **конкретного маршрута и запроса**, не означает недоступности всех Bybit API; найденный резерв должен иметь **тот же вид рынка и метрики**, а не просто похожий тикер. Пользовательские скриншоты сохраняют класс пользовательского доказательства, не превращаются в независимый API.

## 5. Открыто и предлагаемое решение

- **S702-01:** среда обычного ChatGPT ещё не доказала самостоятельное обнаружение созданного Skill в GitHub, отрабатывание `When to use` и активное чтение `SKILL.md`. Наличие файла только в репозитории не является установкой.
- **S702-02:** полная проверка YAML через `skills-ref validate`, проверка всех реальных опциональных полей, реальный `node`/CI прогон и независимый ChatGPT blind-run не проводились; статическая проверка 10 относительных путей выполнена.
- **S702-03:** тесты локально измеряют совместимость и TTL на синтетике; не подтверждают живые Bybit V5/OHLCV/Mark/T02, поведение fallback при реальном HTTP403 или различие пользовательской P02.
- **S702-04:** RV-02/RV-03, RV-04/RV-06, TV-01–TV-04, FR-038 F/V/H/R и фактический `READY` остаются открытыми.
- **S702-05:** будущие Skills risk-assessment/portfolio-analysis должны заново проверять полный риск; входной quality gate не подтверждает отдельные расчёты IM/MM, liquidation, Short loss.
