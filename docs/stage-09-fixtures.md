## 1. Реализованные артефакты и граница доступа

- **Публичный input-only JSON:** [`tests/fixtures/stage-09/inputs.v1.json`](../tests/fixtures/stage-09/inputs.v1.json) — 45 полностью синтетических сценариев, 41/41 привязка по `prompt_id` к P08-01–P08-41, ещё 4 дополнительных случая.
- **Этот каталог** — группировка по задачам без `expected_status`, `golden_answer`, правильных числовых выводов и ожидаемого маршрута.
- **Экспорт только пользовательского входа:** [`tests/stage-09-02-export-agent-input.mjs`](../tests/stage-09-02-export-agent-input.mjs) — читает выбранный `S09-NNN` и выводит только `user_message` и `payload` без `case_id`/`prompt_id`/`family` и без oracle. Никаких сетевых вызовов.
- **Локальная проверка** — [`tests/stage-09-02-fixture-integrity-synthetic.mjs`](../tests/stage-09-02-fixture-integrity-synthetic.mjs). Она валидирует структуру, уникальность, синтетический режим/даты, отсутствие ожидаемых результатов, полноту P08, корректность OHLCV и предметное покрытие. Она **не тестирует ответы ChatGPT**.
- **Журнал шага / self-review:** [`stage-09-02-validation.md`](stage-09-02-validation.md).

**В публичный GitHub категорически не записывать до завершения blind-run:** приватную oracle-card для любого S09 ID, допустимый/обязательный `verdict`, ожидаемый `RT`, фактическую оценку ещё не выполненного запуска, скрытый prompt с golden output. Если эти сведения утекли в контекст оцениваемого агента, `LLM_BLIND` для соответствующего запуска **дисквалифицирован**; нужен новый независимый тест по версии/изолированному входу. Пустую oracle-card можно подготовить в отдельном приватном контуре позднее — **реальные oracle здесь НЕ СОЗДАНЫ и НЕ ХРАНЯТСЯ**. Технически проверить отсутствие неизвестных скрытых публичных ссылок нельзя; проверяется только текущая структура и опубликованное содержимое.

## 2. Формат входного пакета

Один объект `cases[]` содержит:

| Поле | Назначение |
|---|---|
| `case_id` | Неповторимый стабильный `S09-NNN`; серия S09-001…S09-045 |
| `fixture_version` | `1`, изменение контента требует новой версии и фиксации исходного blob/commit |
| `synthetic` | Всегда `true`, без претензии на достоверный источник |
| `synthetic_now_msk` | `2026-10-20T12:00:00+03:00`, фиксированное **тестовое время**, не реальная текущая дата ответа |
| `family` | Категория сбора coverage, **служебная метаинформация**, не передавать агенту |
| `prompt_id` | P08-01…41 или `null`, **служебная привязка** к одному из принятых пользовательских шаблонов |
| `user_message` | Дословное тестовое сообщение, с явным предупреждением `SYNTHETIC` |
| `payload` | Только синтетические дополнительные данные и, для отдельных кейсов, компактные OHLCV |

**Локальная команда экспорта (при реальном Node.js checkout, здесь не запускалась):**

```bash
node tests/stage-09-02-export-agent-input.mjs S09-001
```

Вызов проверяемого агента на 09.4–09.8: передать **содержимое `user_message` и `payload`** вместе с соответствующим P08-шаблоном/применимыми утверждёнными инструкциями и точным `GitHub commit SHA`. `family`, `case_id`, `prompt_id` — для журнала исследователя, **не добавлять их как подсказки агенту**, равно как и это оглавление, ожидаемые результаты или отчёт self-review. При переносе исходного JSON к агенту в полном виде он увидит служебную метаинформацию — такой прогон **нельзя считать строго слепым по маршрутизации**. Лучше формировать отдельный `agent_input` без служебных полей.

Ценовые поля со словом Bybit в фикстурах **не являются реальной биржевой информацией**, даже если метка рынка выглядит правдоподобной. Нельзя использовать их для live R3 либо принятия торгового решения. Все позиции, счета, комиссии, источники, цены и скриншоты — вымышленные. Данные синтетических `T02/T03/T04/T05/T06` не являются персональными данными пользователя; T01 описан в каждом `user_message`.

## 4. Данные свечей и времени

S09-006 содержит **110 закрытых синтетических 1h** и **90 закрытых синтетических 4h** баров SOLUSDT. S09-008 намеренно содержит всего **12 закрытых 1h** баров. Формат каждого бара — `[open_time_ms_utc, open, high, low, close, volume]`. Все времена UTC epoch milliseconds; фиксированное `TEST NOW` — 12:00 МСК (+03:00). 1h last bar закрывается в 12:00 МСК, 4h last bar — в 11:00 МСК. Это исключительно сформированные формулой тестовые числа, а не реальные OHLCV Bybit; одинаковая формула не гарантирует физически реалистичную ликвидность/котирование.

Там, где OHLCV, полный T02, T04/P02, source/time или строгая Cross/Short risk model **не приложены**, намеренно оставлен `null/UNKNOWN`; ничего не домысливать. T06/H02/H03 могут отсутствовать — отсутствие истории не равно автоматически активному H04. Состав P08 и данное тестовое время **не разрешают** брать реальную цену через API и объявлять тест действительной торговой рекомендацией.

## 5. Подготовка к независимому прогону, который ещё не состоялся

1. В 09.3 зафиксировать GitHub blob SHA/commit, версию input, способ загрузки реальных `.agents/skills`, разделение входа и служебных полей; настоящий independent runtime может оказаться `NOT_VERIFIED`.
2. Перед первым blind-run независимый оценщик вне публичного контекста создаёт закрытый oracle для выбранного `case_id`, **не** публикует до получения raw transcript; если надёжное приватное хранение недоступно, не заявлять blind-run со скрытым oracle.
3. В 09.4–09.8 отдельная новая сессия получает `user_message`/`payload` и нормативные инструкции; фиксировать фактически прочитанные Skill files/SHA, сырой ответ и оценку только после завершения.
4. После оценивания можно публиковать полностью обезличенные результаты с подробным provenance, но нельзя менять старые записи; исправление создаёт новый commit/fixture version и rerun.
5. Если сценарий провоцирует реальные API/приказы, исполнение строго запрещено. Только анализ SYNTHETIC, нет live READY.
