# Входные данные пользователя — шаблоны для Crypto Trading Agent (шаг 04.5)

> **Статус: РЕАЛИЗОВАНО ПО СОГЛАСОВАННОЙ СТРУКТУРЕ; ОЖИДАЕТ ИТОГОВОЙ ПРИЁМКИ ПОЛЬЗОВАТЕЛЕМ (14.10.2026).** Шесть контекстных шаблонов T01–T06 являются инструкциями для общения с агентом, **не** формами биржевых API и **не** списком полей реальной версии Veles/GinArea. Документ не означает самостоятельного доступа ChatGPT к приватному Bybit, подключение торгового счёта или возможность выдать READY. Шаги 04.1–04.4 утверждены ранее; к 04.6 не переходить без согласования.

Основания: [план шага 04.5](stage-04-plan.md#7-шаг-045--шаблоны-предоставления-пользовательских-данных), [40 категорий и правила резервов](data-sources.md), [актуальность 04.4 / RV-05](data-freshness.md), [FR-018–FR-053](requirements.md), [сквозные правила](agent-operating-rules.md), [архитектура и конфиденциальность](architecture-decisions.md). Все описанные значения в примерах — **заполнители**, не реальные данные пользователя.

## 1. Принцип: небольшая просьба под текущую задачу

**Не отправлять пользователю все шесть шаблонов сразу.** Агент должен определить цель (рыночный обзор, анализ инструмента, подготовка входа, сопровождение позиции, проверка бота, восстановление серии), применимость риска и только недостающие сведения. Пользователь вправе отправить **скриншот, экспорт/JSON или обычный текст**; это равноценные способы доставки, но не равноценные гарантии полноты и подлинности.

**Классы обязательности:**
- **О — обязательное:** без этого нельзя обосновать конкретный заявленный результат; для READY применяется весь обязательный набор текущего и будущего риска. Если исходные сведения уже получены, не просить повторно до устаревания/изменения.
- **У — условно обязательное:** нужно только при выполнении условия (есть действующая позиция/бот, Cross, связанная серия, выбран конкретный индикатор, готовится READY). Не существует обязанности прикладывать сведения о неиспользуемых стратегиях.
- **Д — дополнительное:** повышает контекст или полноту; отсутствие само по себе не блокирует текущий результат.
- **И — историческое (RV-01):** H02/H03 по возможности; отсутствие достоверной истории **не** отдельная блокировка READY, проверка записывается NOT_CHECKED. **Не путать** с H01 — обязательной историей конкретной связанной серии, когда рассчитывается её восстановление.

**Режимы:** R1 = обзор, R2 = предварительный торговый сценарий, R3 = проверка итоговой конфигурации на READY. Пороговые интервалы, источники времени и их ограничения находятся в [data-freshness.md](data-freshness.md); **одного соблюдения TTL недостаточно для READY**.

| Шаблон | Когда запрашивать | Вид ввода | Классы данных |
|---|---|---|---|
| **T01 — задача** | В начале неоднозначного сценария, только недостающее | Сообщение, при необходимости ссылки/рыночный JSON | U01–U03; дополнительные M/D/N |
| **T02 — весь фьючерсный счёт** | При проверке совокупного риска, до R3 | Актуальные снимки/экспорт и явное подтверждение охвата | A01–A04, A07–A08; дополнительно A05–A12 |
| **T03 — конкретная позиция** | При сопровождении позиции и если она есть в портфеле | Снимок позиции/текст с датой | A05–A06, M02; применимое A11 |
| **T04 — бот и полная сетка** | При работе с Veles/GinArea и будущими IN | Скриншоты действительной формы, выгрузка уровней/текст | A08–A11, P01–P02 |
| **T05 — связанная серия сделок** | Только при восстановлении результата конкретной серии | История исполнения/комиссий/funding | H01 |
| **T06 — история Equity и известных нарушений** | Необязательные дополнительные проверки истории | Датированная история и денежные потоки; без неё NOT_CHECKED для H02/H03 | H02–H04 |

**Публичная рыночная информация не превращается в седьмую обязательную анкету:** агент сначала ищет доступные публичные M/D/N по [реестру источников](data-sources.md#14-маршрутизация-по-всем-40-категориям-данных). Если нужного поля нет, предлагает пользователю прислать точный **публичный** Bybit JSON, датированный график, источник новости или измерения прямо в контексте **T01/T03/T04**. Рынок другого инструмента/биржи и скриншот без подписи не заменяют Bybit Mark для ликвидации.

## 2. T01 — описание задачи и рыночные источники

**Запрашивать минимально:** можно начать с фразы «Проанализируй монету …», если задача и актив ясны. Не нужно спрашивать капитал для объяснения RSI или общего обзора. Для конкретной стратегии уточнять только недостающее.

| Поле / вопрос | Обязательность | Как заполнять |
|---|---|---|
| Что нужно сделать: обзор / анализ пары / новая позиция / сопровождение / восстановление / пересмотр бота | **О** для выбора сценария (U01) | Короткая фраза; при ясном запросе не переспрашивать |
| Биржа + точный инструмент + тип рынка | **О** для анализа конкретного инструмента (M01) | Например, «Bybit, [СИМВОЛ]USDT, Linear Perpetual»; если нужен поиск монеты, тикер может быть неизвестен |
| Направление, горизонт, таймфреймы, бюджет, платформа, целевые ограничения | **У** (U02) | Только те, что определяют текущий сценарий; различать **номинал первого IN** и **доступную маржу** |
| Пользовательский выбор сценария после сравнения вариантов | **У** (U03) | Подтверждается пользователем **после** обсуждения, не предполагается по умолчанию |
| Рыночные данные или новости, которые не удалось найти агенту | **У/Д** (M/D/N) | Публичный Bybit Kline/Tickers/Instruments Info/Risk Limit, точная дата/источник и рынок; официальная публикация с временем; альтернативы только по 04.3 |

**Короткий копируемый вариант:**

> Задача: [обзор / анализ / сопровождение / новая позиция / бот / восстановление]  
> Инструмент и рынок: [биржа, точная пара, Spot или USDT Perpetual]  
> Горизонт и направление (если нужно): [период, Long/Short/оба]  
> Платформа и бюджет (только для бота): [Veles/GinArea/другая, размер и единица]  
> Дополнительные ограничения / ссылки: [если есть]

Если ChatGPT не смог получить свежие котировки, он **сам указывает один точный недостающий набор**, например «Нужен свежий Bybit Tickers для этой пары с markPrice и response_time», а не требует заполнить всю матрицу.

## 3. T02 — актуальное состояние ВСЕГО фьючерсного счёта

**Назначение:** R2 для анализа портфеля и **О для R3**. Один экран с отдельной позицией **не** подтверждает полный охват. Необходимо учесть все относящиеся к риску UTA/субсчета, активы обеспечения и активные/условные обязательства. На R3 **каждая существенная часть снимка ≤5 минут + подтверждение отсутствия существенных изменений**, иначе запросить новый комплект; несколько изображений должны относиться к одной контрольной точке или быть корректно согласованы.

| Секция | Поля, которые необходимо видеть | Класс |
|---|---|---|
| **A01. Охват** | Bybit (тип счёта, UTA/режим), какие фьючерсные счета/субсчета включены, часовой пояс и **snapshot_at** каждой части | **О для R3** |
| **A02. Equity и обеспечение** | **Equity** с валютой оценки, состав мультивалютного обеспечения, если используется; отделить Equity, баланс и доступные средства | **О для R3** |
| **A03. Маржа** | Доступная и занятая/начальная/поддерживающая маржа, прочие обязательства и резервы в валюте источника | **О для R3** в объёме, необходимом для риск-модели |
| **A04. Все позиции** | Полный список (включая пустые разделы), символ, Long/Short, размер и режим; явное подтверждение «других нет» только если это достоверно | **О для R3** |
| **A07. Все ордера** | Активные, условные, триггерные/отложенные, направление и статус, способны ли увеличить позицию, reduce-only/close-on-trigger | **О для R3** |
| **A08. Все боты** | Действующие и приостановленные Veles/GinArea, управляемая позиция/инструмент; если отсутствуют — явное подтверждение | **О для R3** |
| **A05–A06. Детали позиций** | T03 на каждую открытую позицию или полная выгрузка, биржевой Mark/ликвидация (если отображаются), Cross/Isolated и One-Way/Hedge | **У→О при наличии позиций** |
| **A09–A12. Будущая нагрузка и стресс** | Полные T04 для всех актуальных ботов, выбранной новой сетки, требуемая корреляционная/стресс-информация; вычислимые нагрузки и комиссии — после подтверждения источников | **У→О для соответствующих риск-проверок** |

**Запрос агентом:** «Пришли, пожалуйста, актуальный обзор Equity/маржи, **все** позиции, **все** активные и условные ордера, действующие боты и полные планы IN. Если одна из секций пуста, подтвердить это словами. Укажи время и охват; можно несколькими скриншотами или одной выгрузкой».

**Текстовое сопровождение к снимкам:**

> Снимок создан: [дата-время и часовой пояс]  
> Охват: [все относящиеся счета/субсчета; UTA; Cross/Isolated по применению]  
> Файлы: [список скриншотов/экспортов по секциям]  
> Все позиции показаны: [да / нет / не уверен]  
> Все активные и условные ордера показаны: [да / нет / не уверен]  
> Все действующие боты и будущие IN показаны: [да / нет / не уверен]  
> После создания снимка изменения: [нет / есть, какие / не знаю]

В **публичный GitHub** помещается только этот текст **с заполнителями**. **Не** размещать реальные Equity, UID, снимки, истории, идентификаторы операций, адреса или ключи. В приватной беседе пользователь может закрыть личные идентификаторы, **не закрывая существенные поля**. Не требовать раскрытия API-ключей или паролей даже в личном чате.

**Контроль полноты:** на все части должен приходиться один связный охват; нельзя считать, что не показанные страницы «пусты»; сокращённый/обрезанный экран, спорная единица маржи или отсутствие данных Cross → NEEDS_DATA / UNVERIFIED. В частности, публичный Risk Limit **не** содержит маржу или фактическую риск-ступень пользователя.

## 4. T03 — карточка открытой позиции

**Условие:** нужен при разборе позиции, но **не заменяет T02** перед READY. Если T02 уже содержит все перечисленные сведения, достаточно ссылаться на этот материал и не спрашивать повторно.

| Сведения | Класс / трактовка |
|---|---|
| Контракт, биржа, USDT Perpetual или иной рынок, сторона Long/Short, активность | **О** при разборе позиции |
| Размер позиции и единица (BTC/контракты/USDT), номинал, средняя цена входа | **О** для количественного анализа |
| Cross или Isolated, One-Way или Hedge, фактически заданное плечо | **У→О** для оценки обеспеченности и ликвидации |
| Отдельно **Last / Mark / Index** при необходимости, источник, время измерения и валюта | **О для актуального риска: именно Bybit Mark** |
| Биржевая liquidation price (если отображается), первоначальная/поддерживающая маржа, PnL с уточнением реализованный/нереализованный | **У→О** в объёме применимой риск-методики; отсутствие ликвидации не подменять грубой формулой Cross |
| Имеющиеся стопы, частичные выходы, условные ордера, связь с ручным управлением/ботом | **У** для сопровождения, покрытие всех ордеров дополнительно через T02 |

**Удобный минимум в чате:**

> Позиция: [символ, биржа, тип рынка, Long/Short]  
> Время снимка: [дата/время/часовой пояс]  
> Размер, вход, плечо, режим: [значения / приложенный полный скриншот]  
> Mark и ликвидация: [явно подписанные данные / не показано]  
> Стопы/управляющий бот: [есть / нет / неизвестно]  
> Цель: [что решить сейчас]

Для R3 соблюдать [правила 04.4](data-freshness.md): **Mark ≤2 минуты** по надёжной временной метке, а состояние полного счёта **≤5 минут** с подтверждением отсутствия изменений. Если старый скриншот прислан только что, время пересылки **не обновляет** время рынка. При ненадёжной Cross-модели статус **UNVERIFIED, не READY**, даже если снимок свежий.

## 5. T04 — действующий или предлагаемый бот и ПОЛНАЯ сетка

**Важно:** это **универсальная схема сбора сведений**, а не перечень реальных названий полей платформы. Нельзя придумывать «существующие поля GinArea PRO» или Veles. Конкретное название и допустимый диапазон подтверждать **фактической формой той же версии** либо её официальной документацией (P01); перед R3 нужен **пользовательский снимок заполненной формы** (P02).

| Группа | Что нужно и почему | Класс |
|---|---|---|
| Идентичность | Veles/GinArea, версия/тип формы, тип бота, точный инструмент, направление, текущий статус, назначение | **О для настройки бота** |
| Реальные поля (P01) | Скриншот **всех доступных разделов формы**; названия, значения, переключатели, требования платформы, возможность управления уже открытой позицией | **О для проверяемой конфигурации** |
| Исполненные и текущие IN (A09) | Исполненные уровни/объёмы, что уже включено в биржевую позицию, комиссия/время при применимости | **О при действующем боте/позиции** |
| **ВСЕ будущие IN** (A09) | Каждый уровень или однозначный алгоритм его построения из **подтверждённых настроек**, направление, цена/триггер, количество или номинал с единицей, число повторов | **О до финального расчёта риска**, в том числе если биржа ещё **не размещала** эти ордера |
| Маржа/экспозиция (A10/A11) | Плечо, схема выделения маржи, требуемая сумма для полного будущего заполнения, комиссии/funding/проскальзывание/стоп и план выхода | **У→О** для применимой риск-модели R3 |
| Связь и владение (A08/A07) | Какие позиции/ордера на Bybit относятся к этому боту, ручное или автоматическое управление, исключения двойного счёта | **О для R3 при наличии ботов** |
| Итоговый снимок (P02) | Фото/экспорт **реально заполненной** конфигурации после выбранного пользователем варианта | **О для финальной проверки READY**, **не** в самом начале обсуждения |

**Текстовая карточка:**

> Платформа и фактическая версия формы: [Veles/GinArea; приложен полный экран]  
> Инструмент / направление / статус: [значения]  
> Уже исполненные IN: [выполнено, цены и номиналы; или «нет»]  
> Будущие IN: [полный список уровней или подтверждённый алгоритм]  
> Биржевые ордера этого бота: [сопоставление / неизвестно]  
> Выход, стоп, ограничения: [что реально есть в форме]  
> Итоговая заполненная форма: [скриншот — только на этапе финальной валидации]

**Для длинной сетки допускается таблица**, но без придумывания значений:

| Уровень | Статус: исполнен / уже на бирже / будет выставлен ботом | Цена или триггер | Размер + единица | Чья экспозиция |
|---|---|---|---|---|
| [IN-01] | [статус] | [условие] | [объём/номинал] | [ручная/бот/уже учтено] |
| [IN-02] | [статус] | [условие] | [объём/номинал] | [ручная/бот/уже учтено] |
| […] | […] | […] | […] | […] |

**Проверка:** 100% будущих IN плюс буферы, лимит загрузки маржи **≤30% Equity**, лимит убытка бота **≤5% Equity**, плечо **≤5×**, ликвидационное расстояние **≥15% от Mark** при неблагоприятном ходе, **≤3** реальные/потенциальные фьючерсные позиции и применимые стресс-тесты **не отменяются** шаблоном. Формулы и гарантия пригодности Cross относятся к этапу 05. Если формула риска невалидна или форма неподтверждена — **UNVERIFIED**, даже если поля заполнены.

## 6. T05 — история СВЯЗАННОЙ серии сделок (не история всего Equity)

**Условие:** только когда цель — **восстановить финансовый результат согласованной связанной серии** или компенсировать ранее реализованные убытки именно этой стратегии. Для общего обзора или нового независимого бота не запрашивать.

| Элемент | Класс |
|---|---|
| Критерий связи сделок и границы серии: инструмент, время начала/окончания, что включаем и исключаем | **О** для восстановления |
| Все исполненные входы/выходы и закрытые части, направление, объём, стоимость и время | **О** |
| Реализованные прибыли/убытки в валюте оценки, уже закрытые части, комиссии и funding за период | **О** для чистого результата |
| Текущая открытая часть, её размер, нереализованный PnL, связанное с ней обеспечение и датированная Mark | **У→О при открытой позиции** |
| Цель пользователя: вывести связанную серию «в ноль» или достичь другого чистого результата | **У**; после расчёта обсуждается отдельно |

**Короткий запрос:** «Пришли датированную историю **именно всех связанных исполнений** с комиссиями, funding, закрытыми и открытыми частями. Уточни границы серии и желаемый **чистый** результат. Если часть данных неизвестна, скажи, какая».

**Безопасность вычисления:** реализованный PnL, ещё открытый PnL, комиссии и funding должны учитываться без двойного счёта по одной методике. Если пропущена часть исполнений или расходов, итог серии не объявлять подтверждённым; **NEEDS_DATA/UNVERIFIED**. Нельзя утверждать, что прибыль одного нового выхода означает восстановление предыдущих потерь. Наличие/отсутствие полной истории Equity (T06) для этого вывода не является эквивалентом T05.

## 7. T06 — НЕОБЯЗАТЕЛЬНАЯ история Equity и известные нарушения

**Это особый шаблон RV-01.** Не включать историю всего Equity в обязательный пакет READY. Если данных нет, исторические H02 (просадка до 15%) и H03 (дневной убыток до 3%) помечаются **NOT_CHECKED** без выдуманного «в пределах лимита» и без автоматического REJECTED. Но достоверно известное **H04 — нарушение и его статус — нельзя игнорировать**.

| Исторические сведения | Класс и применение |
|---|---|
| **H02.** Достоверная последовательность Equity и исторический максимум с валютой оценки; даты пополнений/выводов, влияющие на базу | **И** — если имеется, для дополнительного контроля 15% |
| **H03.** Equity на **00:00 Europe/Moscow** в начале соответствующих суток, пополнения/выводы и динамика результата | **И** — если имеется, для дополнительного контроля 3% |
| **H04.** Известное ранее подтверждённое нарушение, срок действия ограничения, подтверждённое восстановление/разблокировка | **У/О при известном факте** — не игнорировать в риск-решении |
| Источник, охват, временная зона, надёжность и неполные интервалы | **О для вычисления исторического показателя**, когда он всё-таки заявляется проверенным |

**Текст по желанию пользователя:**

> Полная история Equity: [есть / нет / частичная]  
> Период, валюта оценки и источник: [при наличии]  
> HWM и пополнения/выводы: [при наличии]  
> База Equity на 00:00 МСК и движения в сутки: [при наличии]  
> Известные нарушения 15%/3% и их статус: [есть, подтверждение / неизвестно / достоверно нет]  

**Не подменять:** «нет истории» ≠ «нарушений не было». Достоверно выявленное нарушение по действующим FR-028/FR-035/FR-036 блокирует действия по увеличению риска, пока не выполнены условия. При отсутствии истории H02/H03 = NOT_CHECKED. **H01 из T05 не заменяется этой историей**, если требуется точный чистый результат серии.

## 8. Проверка данных из файлов, изображений и текста

**Общий контроль после получения каждого входа:**

1. **Привязка:** где источник, какой счёт/инструмент/платформа, Long/Short, Spot/Linear Perpetual, тип Mark/Last/Index, период и единицы (BTC, контракты, USD, USDT, %, доля).
2. **Время:** явный UTC/offset или Europe/Moscow; для Bybit JSON поле времени ответа сервера — **response_time**, не индивидуальный observed_at каждого показателя; время пересылки — **retrieved_at**, не момент рынка. Время скриншота — snapshot_at, если обосновано. Открытая свеча не закрыта автоматически.
3. **Свежесть:** R3 — Mark ≤2 мин, полный портфель ≤5 мин и подтверждение неизменности; если используются как обязательные входы, OI ≤15 мин, funding ≤10 мин, спецификации ≤24 ч; стакан для оперативного вывода ориентир ≤30 сек. Для R1/R2 применять отдельные пороги 04.4, **досрочное обновление при событии обязательнее формального TTL**.
4. **Полнота:** одна карточка позиции **не** полный счёт. Подтвердить все страницы/счета/позиции/активные и условные ордера/боты/будущие IN/состояние запланированной формы; отсутствие страницы нельзя считать отсутствием ордеров.
5. **Связность:** разные файлы могут относиться к разным моментам; явно указать расхождения и спросить только недостающую часть/новый пакет. Не склеивать сведения о разных account modes, ставках funding и двух определениях Open Interest.
6. **Пересечения:** биржевой ордер одного бота не добавлять **вторично** при суммировании экспозиции; сопоставление по символу/стороне/цене/объёму и подтверждённой связи; не делать автоматический вывод о принадлежности по одному совпавшему размеру.
7. **Защита:** не просить пароли, API-ключи, токены, UID, seed-фразы, адреса, номера счетов и персональные отчёты; не копировать приватные снимки, реальные балансы, сделки или сырые текущие котировки в публичные GitHub Issue, PR, коммиты и примеры. Данные, которые пользователь добровольно прислал в приватном чате, остаются материалом текущего анализа.
8. **Пригодность:** при отсутствующем обязательном значении — NEEDS_DATA, при сомнительной идентичности/времени/методике — UNVERIFIED; подтверждённое нарушение лимита — REJECTED; READY возможен **только** после всех фактически доступных и обязательных проверок текущего/прогнозируемого риска и сверки финальной формы. Согласованные статусы [в agent-operating-rules.md](agent-operating-rules.md#8-итоговые-статусы-и-действия-агента).

### Что показывать пользователю при недостатке сведений

Вместо длинной анкеты: «Для **[точный вывод]** не хватает **[конкретные поля и охват]**. Пришли **[один предпочтительный вид снимка/экспорта]** со временем **[нужный срок]**; до этого могу **[указать, какую предварительную часть анализа можно выполнить]**». Просьбу сформулировать **одной ближайшей операцией**, когда остальные данные пока преждевременны.

## 10. Сценарии использования и комплект документов

| Тип запроса | Что спросить сначала | Какие сведения понадобятся дополнительно |
|---|---|---|
| «Что такое Funding?» | Ничего сверх вопроса | **Никакие** данные счёта и даже тикер не обязательны |
| «Обзор BTC» | T01 только при неясном рынке/горизонте | Публичные M/D/N в доступной части; нет T02–T06 и нет READY |
| «Хочу Short по конкретной паре» | T01, нужный рыночный источник | T02/T03 только для анализа влияния на портфель/финального риска |
| «Что делать с убыточной позицией?» | T01 (цель) + T03 (сама позиция) | T02 при совокупном риске и R3, T04 если задействован бот; T05 **только** при восстановлении серии |
| «Подготовь сетку Veles/GinArea» | T01 + T04 (реальная форма, алгоритм IN) | T02 + применимые T03 перед R3; **P02 — только после выбора/заполнения финальной формы** |
| «У меня серия убытков, нужна цель выхода в ноль» | T01 + T05 с границами серии | T03 если есть открытая позиция; T02/T04 если предлагается увеличить риск |
| «Проверь историческую просадку/дневной лимит» | T01 + T06, **если есть история** | T02 для текущей точки; без T06 исторические проверки **NOT_CHECKED** |
| «Финально проверь бота на READY» | T01, T02, T04, применимые T03, рынок и P02 | Полный риск, стресс и свежесть; T05 только для восстановления серии; T06 не обязателен |

### Два примера общения (только вымышленные формулировки)

**Пример A — один вопрос без приватных данных.**

> Пользователь: «Объясни разницу между Last и Mark Price».  
> Агент: «Для объяснения не нужен ни снимок счёта, ни анкета. Last — цена последней сделки, Mark — расчётная биржевая цена, важная для ликвидации. Если нужно проверить конкретную позицию, уточни инструмент и пришли актуальные данные».

**Пример B — поэтапная подготовка бота.**

> Пользователь: «Хочу Short-бота GinArea на [СИМВОЛ], начальный IN [НОМИНАЛ] USDT».  
> Агент: «Сначала уточню горизонт и проверю доступные рыночные данные по точному Bybit Perpetual; твои скриншоты счёта пока не нужны для предварительного сравнения вариантов».  
> Пользователь выбирает вариант.  
> Агент: «Теперь нужен T04: снимки **действительной** формы GinArea и вся сетка IN. Для финального READY позже запрошу **свежий T02** обо всём счёте, T03 при наличии позиций, а после заполнения — P02. Если ликвидацию Cross невозможно проверить надёжно, статус будет UNVERIFIED, даже при полном комплекте картинок».  
> Агент после получения: «Проверяю, какие сведения отсутствуют, не дублируются ли IN и ордера и не изменилось ли состояние перед финалом. Историю Equity T06 просить не стану без особой причины; H02/H03 получат NOT_CHECKED при её отсутствии».

## 11. Документальная самопроверка (синтетические случаи, не реальные API-тесты)

| ID | Проверяемое условие | Ожидаемый результат |
|---|---|---|
| IT-01 | Пользователь спрашивает значение RSI, без данных аккаунта | Не запрашивать T02–T06; ответить по смыслу |
| IT-02 | Анализ BTCUSDT без портфеля, доступны датированные свечи | Предварительный R1/R2 возможен, READY не утверждать |
| IT-03 | T02 содержит одну позицию, другие страницы счёта не показаны | NEEDS_DATA для полного охвата; не считать отсутствующие строки нулём |
| IT-04 | T02 сделан 4 минуты назад, но с тех пор добавлен условный ордер | Обновить комплект; TTL не отменяет инвалидацию события |
| IT-05 | T03 имеет Last, но не содержит Mark для ликвидации | NEEDS_DATA / UNVERIFIED для расчёта риска, нельзя подменить Last |
| IT-06 | T04 содержит первый IN и два уровня без размеров оставшейся сетки | NEEDS_DATA: неполная будущая нагрузка |
| IT-07 | В T02 и T04 указан один и тот же размещённый ботом ордер | Сверить принадлежность, не удваивать экспозицию; при неясной связи — уточнить |
| IT-08 | Нужна цель восстановления серии, T05 содержит только последний прибыльный выход | NEEDS_DATA: все связанные исполнения/комиссии/funding отсутствуют |
| IT-09 | Не представлены T06 H02/H03, но обязательный текущий риск **независимо** подтверждён | H02/H03 = NOT_CHECKED; отсутствие истории Equity само по себе не блокирует READY; все остальные обязательные проверки текущего и прогнозируемого риска должны быть успешно пройдены |
| IT-10 | Достоверно известно нарушение H04, которое не снято | Ограничить увеличение риска / REJECTED для нарушающего сценария |
| IT-11 | Скриншот GinArea другой версии, итоговый P02 отсутствует | Поля не подтверждены → UNVERIFIED; READY запрещён |
| IT-12 | Cross, вся информация свежая, но ликвидация и предельный убыток ненадёжно моделируются | UNVERIFIED; полнота формы и TTL не подтверждают READY |
| IT-13 | Пользователь прислал Tickers с давним response_time только что | Использовать **время исходного ответа**, а не время пересылки; актуальная Mark нужна новая |
| IT-14 | Для новостного события доступна датированная BY-N статья, но X 403 | Проверить само событие по BY-N, не утверждать, что конкретный пост X или X sentiment прочитан |
| IT-15 | Пользователь приложил старый полный T02 и новый одиночный T03 | Комбинация не подтверждает актуальный полный портфель; попросить свежий T02 перед R3 |
| IT-16 | Для предполагаемой новой позиции ещё не выбран вариант стратегии | Не считать U03 подтверждённым и не перепрыгивать к утверждению параметров бота |

**Контрольный результат:** 16 сценариев имеют предусмотренное текстом решение; покрываются все шесть шаблонов, обязательность/условность/история, источник/время, двойной счёт и границы READY. Это **нормативная самопроверка документа**, а не реально исполненные API/торговые тесты; полноценная приёмка сценариев — шаги 04.7–04.8.

## 12. Итог и границы шага 04.5

- Состав **T01–T06** соответствует утверждённому плану. **Все 40 категорий** имеют маршрут/шаблон в §9; **не** все 40 значения доступны автоматически. В отсутствие прямого Bybit API резерв — датированный пользовательский JSON/экспорт/скриншот при соответствующей проверке актуальности и подлинности.
- **T02 + применимые T03/T04** являются путём получения полного текущего риска, но **не** готовой моделью Cross или источником индивидуального биржевого доступа. Все строгие FR-027–FR-040 действуют независимо от заполнения.
- **T05 обязателен только для цели чистого результата связанной серии; T06 H02/H03 необязателен (RV-01).** Известный H04 влияет на решение независимо от полноты истории.
- **P01** должен проверяться по реальной форме/документации **именно существующей версии платформы**, **P02** — итоговая пользовательская проверка после заполнения. Названий вымышленных настроек Veles/GinArea нет.
- Никаких API-ключей, UID, паролей, реальных личных позиций, сумм, снимков счёта, приватных отчётов или исполняемого автосбора в публичном репозитории.

**Статус:** документ подготовлен по согласованному решению пользователя. **Шаг 04.5 ожидает отдельной приёмки по итогам самопроверки; 04.6 не начат.**
