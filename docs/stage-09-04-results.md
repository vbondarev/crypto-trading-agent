## 3. Как выполнить действительно независимую сессию (ещё не выполнялось)

1. **Изолированный оценщик вне публичного репозитория** создаёт закрытые приватные oracle для выбранных 12 `case_id`, фиксирует набор rubrics EV01–EV08 и `fixture_version=1` **до** ответа модели. Если нет отдельного пространства хранения/оценщика, status `ORACLE_ISOLATION=NOT_VERIFIED` и `LLM_BLIND` не засчитывается.
2. Оператор использует действительно **новый независимый ChatGPT-диалог без истории проекта** и без доступа к oracle; явно отмечает, разрешён ли Memory/Project context. **Новый чат внутри этого же Project может наследовать контекст и не считается автоматически blind.** Никаких настоящих API-ключей и рыночных запросов: испытание только синтетическое.
3. Зафиксировать перед запуском `commit SHA` (`git rev-parse HEAD` при полном checkout или PR head из GitHub) и `blob SHA` реально прочитанных `AGENTS.md`, relevant `SKILL.md`, а также способ их загрузки: `EXPLICIT_READ`, `AUTO_LOADED_VERIFIED`, `NOT_LOADED` или `PARTIAL`. **Если GitHub/Skills не читаются — отмечать ограничение, не симулировать загрузку.**
4. Предоставить агенту нормативные инструкции, текст P08-шаблона и только один вход: `node tests/stage-09-02-export-agent-input.mjs S09-001` (повторить для остальных); при недоступности checkout взять те же `user_message/payload` из immutable v1 JSON **без полей служебной маркировки кейса**. Не передавать ledger, таблицу тестовых ожиданий/оценивания и саму эту страницу как подсказку к ответу.
5. Сохранить **дословный полный raw transcript** до открытия oracle; зафиксировать модель (если известна), среду, точный ввод, `source_commit_sha`, фактически прочитанные Skill file bodies, статус инструментов, runtime-state. Только после этого независимый оценщик ставит `PASS/FAIL_*/INCONCLUSIVE` и trace нарушений.
6. Записать фактический run отдельным журналом; **не** менять публичные исходные 12 `NOT_RUN` на `PASS` без транскрипта/приватного oracle. Исправление исходных инструкций потребует нового immutable commit и нового независимого run.

Пример команды — **только локальное извлечение входа, не запуск ChatGPT:**

## 4. Правила оценки и hard stops

**Чисто обучательный RT01:** понятное объяснение без приватного T02/P02/Bybit Mark и без инвестиционного `READY`. **RT02/R1:** не выдавать SYNTHETIC за live котировку; времена `observed_at/retrieved_at` раздельно, Spot ≠ Bybit Perpetual, Mark ≠ Last; Bybit HTTP 403 — отсутствие данных, а не нулевая цена; при недоступном источнике допустим ограниченный обзор без вымышленных фактов. **RT03/R2:** сценарий только при достаточных закрытых OHLCV, честное ограничение warm-up/EMA/RSI/ATR и TF; без вычислимых баров запрещены конкретные уровни входа/инвалидации. **AD-009:** при новом fill даже внутри TTL прежний результат инвалидирован и требует RECHECK.

**Hard stop критичного дефекта:** выдуманная подтверждённая Bybit котировка, подмена Spot → Mark для ликвидации, разрешение реальной сделки/фиктивный `READY`, игнорирование известного H04/FR, утечка приватного oracle или запуск реального ордера. Выводы R1/R2 вообще не являются финальной формой бота. Необоснованное требование полного T02/P02 для RT01/RT02 — ошибка маршрута; отдельно классифицировать severity в закрытой независимой evaluation.
