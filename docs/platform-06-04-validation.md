# Протокол 06.4 — GinArea PRO: поля и стратегии

> **Статус: IMPLEMENTED / PENDING USER REVIEW (16.10.2026).** Пользователь принял [06.3](platform-06-03-validation.md) и разрешил шаг 06.4 командой «Дальше». Подготовлена [документальная карта GinArea PRO](platforms/ginarea.md) с 14 официальными источниками G-01–G-14, 40 элементами/разделами GD-01–GD-40, 10 правилами совместимости C-G01–C-G10 и 36 нормативными сценариями GG01–GG36. Выполнены **48/48 локальных синтетических JavaScript-проверок Q01–Q48**. Это не проверенная реальная форма P02, не живой тест Bybit или готовый бот. **06.5 не начат.**

## 1. Происхождение, метод и область проверки

Все ссылки G-01–G-14 в [документе GinArea §1](platforms/ginarea.md#1-область-версии-и-реестр-доказательств) — официальная публичная справка, просмотрена 16.10.2026; точная редакция страниц, версия реального PRO-кабинета, состав раскрытых вкладок, тариф, валюта/диапазоны значений **неизвестны**. Bybit UTA, Cross, One-Way, ограничение Hedge для non-Default — **документальные правила**, не фактически проверенная позиция пользователя. Аккаунты, API-ключи, приватный T02 и реальные IN/OUT не использовались.

**Метод:** в изолированной локальной JavaScript-среде вычислены простые синтетические функции compatible, sizeSeq, floorStep, net, signals, stopIN, simpleLev, decide, updateSnapshot. Точные результаты bool/string/number сравнивались Object.is с заранее заданными эталонами. Это **не программный код агента и не тест платформы**. Арифметика на JS Number (IEEE 754) может содержать двоичные хвосты, например 0.15 отображается 0.15000000000000002. Нельзя трактовать такие тесты как проверку Decimal, округлений qtyStep или конкретных лимитов Bybit.

## 2. Фактически исполненные локальные проверки Q01–Q48

| Группа | ID | Что проверялось | Результат |
|---|---|---|---|
| A. Совместимость | Q01–Q09 | Default Hedge условно документирован; non-Default Hedge и Isolated по ограничениям Bybit отклонены; неизвестный UTA запрашивается отдельно | **9/9 PASS** |
| B. Размер ордера | Q10–Q20 | IN 0.1 BTC с множителем 1.5 и cap 0.3 → 0.1, 0.15000000000000002, 0.225, 0.3; другая серия 20+40+50+50+50 = 210; floor по qtyStep, но **только условный** | **11/11 PASS** |
| C. One-Way неттинг | Q21–Q24 | Long4/Short4→0; Long8/Short3→+5; Long3/Short8→−5; виртуальная пара направлений ≠ два Hedge слота | **4/4 PASS** |
| D. Indicator | Q25–Q28 | AND(true,false)→false, OR(true,false)→true, OR(false,false)→false, AND(false,true)→false | **4/4 PASS** |
| E. Disable IN | Q29–Q32 | Выход за диапазон активирует latch; возврат внутрь не снимает его; без активации нет автоматического выключения | **4/4 PASS** |
| F. Плечо/объём | Q33–Q34 | Для фиксированных IN 10×50 / deposit100 = 5; результат не равен серии с множителем и cap | **2/2 PASS** |
| G. Итоговые статусы | Q35–Q40 | REJECTED при несовместимости/H04, UNVERIFIED при конфликте/непроверенной Cross модели, NEEDS_DATA при отсутствии P02, LOCAL_PASS_NOT_READY — не торговый статус | **6/6 PASS** |
| H. Инвалидация | Q41–Q45 | Новый IN, TP, редактирование, restart инвалидируют снимок; простая перерисовка графика — нет | **5/5 PASS** |
| I. Единицы | Q46–Q48 | 20 USDT ≠ 20 монет; Max Size — потолок отдельного IN; выключение % режима ведёт к абсолютным единицам | **3/3 PASS** |

**Итог: 48/48 PASS.** Подробные исходные значения всех Q01–Q48 были получены фактически в одном локальном механическом прогоне; настоящие биржевые изменения не инициировались. Диагностические DOC_ONLY_NOT_P02 и LOCAL_PASS_NOT_READY **не являются пользовательскими статусами торговли**. Q19 использует floating point representation 0.30000000000000004; это не рекомендуемое значение поля. Модель Q29–Q32 — упрощённая логика latch, а не испытание поведения GinArea.

## 3. Нормативные ожидаемые сценарии GG01–GG36

[Таблица GG01–GG36](platforms/ginarea.md#6-нормативные-синтетические-сценарии-gg01gg36) — **36 документальных эталонов**, не 36 независимых ChatGPT-прогонов. Они охватывают реальные отличия размера/максимального размера IN, стратегии и пары, One-Way/Hedge, Cross/Isolated, PRO Dynamic, Indicator Conditions, Disable IN, TP/SL и единицы измерения. Сценарий с требованием проверить текущий селектор конкретной пары остаётся *нормативным*, а не фактом пользовательской P02.

## 4. Самопроверка, нерешённые ограничения

| Критерий 06.4 | Результат |
|---|---|
| Источники, время и scope | G-01–G-14, просмотр 16.10.2026; редакция/реальный PRO version UNKNOWN |
| P01 и ограничения | C-G01–C-G10, Bybit UTA/Cross/One-Way, Default-Hedge документальное исключение |
| Поля | GD-01–GD-40 — **смешанный каталог** полей, заголовков, условных опций и enum; это не полная единая форма P02 |
| Размеры/множители | Per-order Size ≠ Max Size ≠ total position, рассматривать все будущие IN |
| Пары и тариф PRO | Реальный селектор/версия/совместимость на конкретной паре **не проверены** |
| Indicator/Dynamic/DCA | Не переносить специфические поля между стратегиями, PRO Dynamic только по документации |
| Риск | Никакого реального READY; RV-02/RV-03, RV-04/RV-06, TV-01–TV-04 сохраняются |
| Тестирование | 36 ожидаемых синтетических сценариев + 48/48 локальных упрощённых тестов |
| Переход | 06.5 не начат и требует отдельного согласования |

**Остаточные дефекты/неопределённости:** G06-4-01 реальная P02 и её exact labels/min/max/default/видимость неизвестны; G06-4-02 действительная поддержка выбранной пары Indicator Grid не доказана; G06-4-03 multipliers, округление, частичное закрытие/повторный IN требуют подробного lifecycle 06.5; G06-4-04 простая формула плеча из справки не моделирует полную сложную сетку; G06-4-05 стоп, Disable IN, TP и реальные Cross/Short риски недоказаны. При наличии расхождения свежей формы с официальной справкой фиксировать CONFLICT/UNVERIFIED, не угадывать.
