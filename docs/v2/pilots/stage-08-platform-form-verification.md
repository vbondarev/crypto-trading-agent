# Этап 08 v2. Проверка форм Veles и GinArea PRO

Статус `IN_PROGRESS / VELES_P02_VERIFIED / GINAREA_P02_PARTIAL / NO_TRADE_READY`. Цель — подтвердить поля фактических редакторов для выбранного рынка и режима, чтобы агент мог точно сопоставлять параметры неисполняемого черновика с формой.

Основания: [этап 07](stage-07-bybit-public-data.md), [пять синтетических проверок](post-stage-07-synthetic-checks.md), [контракт P02](../../platforms/configuration-contract.md), [адаптер Veles](../adapters/veles.md) и [адаптер GinArea PRO](../adapters/ginarea.md).

| Шаг | Проверка | Критерий | Состояние |
| --- | --- | --- | --- |
| 08.1 | Сверить накопленные наблюдения по редакторам | Для каждого наблюдения указан рынок, режим, время, проверенный объём и открытые пробелы. | PASS |
| 08.2 | Зафиксировать P02 Veles «Простой» | Новый несохранённый редактор Bybit Futures / HYPEUSDT, выбранные направление и режим, видимые разделы и точные названия полей. Для применимых полей фиксируются показанные единицы, ограничения и условия видимости. | PASS для наблюдавшейся формы |
| 08.3 | Зафиксировать P02 GinArea PRO Default Grid | Селектор, рынок, пара и направление, применимые IN/OUT, сетка, стоп и контекст видимых полей. | Селектор проверен, подробный редактор ожидается |
| 08.4 | Сверить черновик с P02 | Каждое сопоставление проверяемо по выбранному режиму и свидетельству. Поля с отсутствующим доказательством помечены. Повторная проверка подтверждает блокировку финализации при недостающем T02 или риске. | Veles PASS, блокировка при частичном GinArea P02 подтверждена |

## 08.1. Что уже подтверждено

- В [пилоте Veles](veles-simple-independent-replay.md#p02-and-pilot-status) 19.11.2026 около 20:32 МСК наблюдались четыре раскрывающихся поля в новом несохранённом редакторе Bybit Futures / HYPE/USDT / LONG / «Простой»: «Перекрытие», «Сетка ордеров», «% мартингейла» и «Отступ». В записи есть отображавшиеся единицы, варианты и диапазоны. Остальные разделы редактора и серверная валидация этой проверкой не покрыты.
- Для GinArea PRO в материалах этого пилота есть адаптер и синтетические сценарии. Подтверждённого наблюдения пользовательского редактора Default Grid для выбранной пары в просмотренных материалах нет.

## 08.2. Требования к наблюдению

Для Veles нужен снимок или запись экрана нового несохранённого редактора DCA с Bybit Futures, HYPE/USDT, направлением LONG и режимом ордеров «Простой». В кадре нужны выбранные рынок, пара, направление, режим и доступные разделы входа, сетки и выходов. Для длинной формы подходят последовательные снимки с перекрытием. Время наблюдения и версия редактора отмечаются при наличии. На снимках скрываются идентификаторы аккаунта, ключи и балансы. Проверка выполняется чтением формы без сохранения или запуска.

Этап относится к идентификации интерфейса. Проверка риска счёта, допуск к исполнению и подключение аккаунта остаются отдельными задачами.

Видимый диапазон плеча 1–75× описывает редактор. Ограничения проекта оцениваются отдельно. Условные поля альтернативных режимов, серверная валидация и биржевое исполнение не проверялись. Значения ордеров не вводились, бот не сохранялся.

## 08.4. Проверка Veles

В офлайн-проверке использована штатная схема и валидатор ветки. Синтетический черновик `NEEDS_DATA` с семью точными названиями полей наблюдавшейся формы прошёл проверку. Значения полей ордеров оставлены пустыми. Попытка повысить статус до `VERIFIED_FOR_MANUAL_REVIEW` при наличии P02 и отсутствии T02 и подтверждения риска отклонена схемой и валидатором. Получены `RISK_UNVERIFIED`, `FINAL_VERIFICATION_NOT_ATTESTED` и `UNSUPPORTED_READY`. Исполнение недоступно. В отдельной офлайн-проверке схема и валидатор приняли синтетический черновик GinArea `NEEDS_DATA` с пятью наблюдавшимися полями селектора и пустыми значениями. При попытке финализации с частичным P02 получены `P02_NOT_VERIFIED`, `RISK_UNVERIFIED`, `FINAL_VERIFICATION_NOT_ATTESTED`, `REAL_MARKET_EVIDENCE_INSUFFICIENT` и `UNSUPPORTED_READY`. Финализация и исполнение заблокированы. Сопоставление полей IN/OUT, сетки и стопа ожидает полного P02.

Селектор пары в редакторе существующего бота работает в режиме только чтения. Редактор закрыт через «Отмена». Наблюдение подтверждает структуру формы для GPSUSDT и служит ориентиром для проверки HYPEUSDT. Единицы и ограничения всех полей для HYPEUSDT остаются неподтверждёнными.

Для 08.4 штатная схема приняла синтетический черновик HYPEUSDT `NEEDS_DATA` с четырьмя названиями по форме GPSUSDT, отмеченными `UNVERIFIED` и оставленными без значений. Отдельная попытка финализации с инструментом GPSUSDT внутри запроса HYPEUSDT отклонена валидатором с `BOT_INSTRUMENT_MISMATCH`, `P02_NOT_VERIFIED` и `UI_FIELDS_UNVERIFIED`. Полный P02 для HYPEUSDT по-прежнему открыт.
