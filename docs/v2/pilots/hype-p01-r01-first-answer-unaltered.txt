## 5. Условные сценарии BULL / BASE / BEAR

Это сценарии для последующей проверки, а не торговые уровни входа.

BULL — восстановление структуры

Условие: последовательное закрепление закрытых 1h/4h свечей выше подтверждённого локального сопротивления, возврат цены выше значимых EMA и подтверждение объёмом.

Инвалидация: неудачный пробой и восстановление структуры более низких максимумов.

Предположение: фундаментальный спрос и закрытие Short способны поддержать восстановление.

BASE — нестабильная консолидация

Условие: отсутствие подтверждённого продолжения снижения либо разворота, разнонаправленные 1h/4h сигналы, слабая определённость объёмов.

Инвалидация: подтверждённый структурный выход из диапазона с последующим удержанием.

Предположение: рынок переходит к накоплению или перераспределению позиций без немедленного тренда.

BEAR — продолжение снижения

Условие: подтверждённый пробой актуальной поддержки закрытыми свечами, сохранение LH/LL и отсутствие убедительного восстановления покупательского объёма.

Инвалидация: возвращение выше пробитой структуры и появление подтверждённого разворота на 4h.

Предположение: ослабление BTC/ETH и сокращение кредитного плеча на рынке способны усилить снижение HYPE.

Вероятности сценариев не рассчитаны. Без непрерывной серии Bybit OHLCV присваивать им проценты или точные ценовые цели было бы необоснованно.

## 6. Решение LONG / SHORT / WAIT

# WAIT

LOW CONFIDENCE

Решение: не рекомендовать открытие новой позиции на основании текущего набора данных.

Медвежий уклон поддерживают опубликованное снижение HYPE, слабость широкого рынка и частичные деривативные наблюдения. Ему противоречат потенциально поддерживающие фундаментальные факторы и отсутствие доказательства того, что снижение продолжится после последнего рыночного снимка.

`SHORT` не выбран автоматически, потому что падение цены не равно подтверждённой точке входа. `LONG` также не подтверждён, поскольку отсутствуют проверенные признаки разворота.

Пересмотр возможен после получения достаточных закрытых свечей, проверки реального режима 1h/4h, подтверждения свежих Mark и OI и устранения критичных конфликтов данных.

Важно: `WAIT` — завершённое аналитическое решение пилота, а не ошибка запуска v2.

## 7. Предварительный проект Veles

Конфигурация: `NOT_RECOMMENDED`

По `docs/v2/bot-handoff-policy.md`, при торговом заключении `WAIT` числовая конфигурация Veles не формируется.

| Поле проекта                   | Значение или статус                          |
| ------------------------------ | -------------------------------------------- |
| Платформа                      | VELES — выбрана пользователем                |
| Биржа                          | Bybit                                        |
| Контракт                       | HYPEUSDT Linear USDT Perpetual               |
| Торговое направление           | WAIT                                         |
| Режим SIMPLE / CUSTOM / SIGNAL | `UNSELECTED`                                 |
| Условия открытия               | `NOT_RECOMMENDED`                            |
| Диапазон сетки                 | `NOT_COMPUTED`                               |
| Число IN-ордеров               | `NOT_COMPUTED`                               |
| Объём первого и будущих IN     | `NEEDS_DATA`                                 |
| Мартингейл и подтяжка          | `NOT_COMPUTED`                               |
| Take Profit / Stop Loss        | `NOT_COMPUTED`                               |
| Плечо                          | `UNSELECTED`; нормативный максимум 5×        |
| Полный маржинальный резерв     | `NOT_EVALUABLE`                              |
| Ликвидационный риск            | `NOT_EVALUABLE`                              |

В репозитории документированы режимы Veles SIMPLE, CUSTOM и SIGNAL, но не подтверждён конкретный режим настоящего пользовательского редактора. Поэтому даже наличие названия поля в справке не разрешает автоматически заполнять его.

Ни GRID LONG, ни GRID SHORT сейчас не получают числового проекта. Это соответствует Gate 0 v2 и не является запретом на последующее проектирование после получения данных.

## 8. Проверка рисков и блокирующих ограничений

Применены действующие жёсткие ограничения из прочитанного `docs/risk-management.md`, а также проверки v2.

| Ограничение                   | Норматив                                            | Результат пилота |
| ----------------------------- | --------------------------------------------------- | ---------------- |
| Плечо                         | ≤5×                                                 | NOT_EVALUABLE    |
| Совокупная Initial Margin     | ≤30% Equity                                         | NOT_EVALUABLE    |
| Максимальный риск одного бота | ≤5% Equity                                          | NOT_EVALUABLE    |
| Одновременные позиции         | ≤3                                                  | NOT_EVALUABLE    |
| Полный резерв будущих IN      | 100% плюс буферы                                    | NOT_EVALUABLE    |
| Запас до ликвидации по Mark   | ≥15%                                                | NOT_EVALUABLE    |
| Дневной убыток, сутки МСК     | Блок при ≥3%                                        | NOT_EVALUABLE    |
| Просадка от HWM               | Блок при ≥15%                                       | NOT_EVALUABLE    |
| Корреляционная нагрузка       | Проверка обязательна                                | NOT_EVALUABLE    |
| Стресс-тесты                  | Обязательны для допуска                             | NOT_EVALUABLE    |
| H04                           | Активное блокирующее состояние запрещает новый риск | UNKNOWN          |

Ни одна строка не получает статус `PASS`. При этом неизвестное значение не трактуется как известное нарушение.

Ключевые ограничения:

- Полный будущий номинал сетки, включая усреднения, не известен. Значит, нельзя проверить совокупную Initial Margin.
- Текущий портфель и режим обеспечения Cross/Isolated отсутствуют. Ликвидация не рассчитана.
- Не подтверждён верхний предел убытка потенциального Short-бота. Один Stop Loss не гарантирует ограничения убытка с учётом проскальзывания и Cross-маржи.
- Стресс-проверки и исторический HWM не проводились.

Итоговый портфельный риск: `UNVERIFIED / NOT_EVALUABLE`. Новая экспозиция не допускается в рамках пилота.

## 10. Один ближайший пользовательский шаг

Предоставить выгрузку закрытых OHLCV-свечей Bybit HYPEUSDT Linear USDT Perpetual.

Предпочтительно — CSV или JSON, по 250 последних полностью закрытых свечей для каждого из таймфреймов `15m`, `1h`, `4h` и `1d`, с UTC-временем, Open, High, Low, Close и Volume. Эти данные публичные, API-ключи не требуются.

После этого можно выполнить воспроизводимый технический расчёт, проверить сигналы и повторно оценить LONG/SHORT/WAIT без изменения GitHub или активации v2.

Итог PILOT HYPE-P01-R01

| Контроль                             | Результат                   |
| ------------------------------------ | --------------------------- |
| Обязательная загрузка v2             | PASS — 9/9                  |
| Дополнительные нормативные документы | 5/5 получены                |
| Публичные источники                  | PARTIAL                     |
| Coin Profile                         | Сформирован с ограничениями |
| Техническая верификация              | INSUFFICIENT                |
| Торговое решение                     | WAIT                        |
| Veles                                | NOT_RECOMMENDED             |
| Проверка портфельного риска          | NOT_EVALUABLE               |
| Реальные торговые действия           | Не выполнялись              |
| GitHub / старый агент / PR #1        | Без изменений               |
| Активация v2                         | Не выполнялась              |

Приёмочный вывод: пилот подтвердил возможность сформировать частичный Coin Profile с реальными источниками, зафиксировать их противоречия и корректно остановить торговую цепочку. Он не подтвердил способность v2 провести полный самостоятельный технический анализ и выдать безопасную конфигурацию Veles. До устранения P1-пробелов результат следует принимать только как ограниченный исследовательский пилот, а не как подтверждение готовности v2 к реальной торговле.
