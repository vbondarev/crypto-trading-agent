## Запрос для повтора

> Для Bybit XRPUSDT USDT Perpetual Long разбери блок «Ордера сделки». Сохрани вход после пробоя верхней полосы Боллинджера на 4ч и ретеста на 1ч. Тип индикаторов — «Гибкие индикаторы». Режим тейк-профита — «Простой», 0,5% от средней цены. На условном максимальном номинале 105 USDT сравни три пресета и ручную сетку «Простого» на минимумы Bybit. Проверь «Свой» с одним ордером 100% и двумя ордерами 60/40 с добором на 0,25%. В «Сигнале» покажи случаи сигнала без расстояния, расстояния без сигнала и выполнения обоих условий. На третьем ордере сравни две базы отступа. Отдельно запиши поля редактора, допущения расчёта и неподтверждённое поведение.

В черновике агент указывает отдельно режим ордеров, общий тип индикаторов и режим тейк-профита. Параметры ниже используются для проверки механики. Точные уровни, серверные ограничения и фактический размер заявок требуют проверки в выбранном редакторе Veles. ## «Простой». Пресеты и ручная сетка

Поля — **«Перекрытие»**, **«Сетка ордеров»**, **«% Мартингейла»** и **«Отступ»**. Первые три значения пресетов взяты с карточек в предоставленной форме. Для теста задан первый вход «Маркет» с расчётной ценой 1,0000 USDT и равный шаг цены по перекрытию. Для ручной контрольной сетки заданы 1% перекрытия, 3 ордера и 1% мартингейла. Доступность этих значений и комбинаций в редакторе для XRPUSDT остаётся предметом проверки. [Настройки DCA](https://help.veles.finance/ru/platform/settings/full/) · [Наблюдение формы HYPE/USDT](stage-08-platform-form-verification.md#082-наблюдение-veles)

Публичный снимок параметров XRPUSDT от **23.11.2026 23:04:24 МСК** получен из Bybit V5 `instruments-info` с `category=linear` и `symbol=XRPUSDT`. Шаг цены **0,0001 USDT**, шаг и минимальное количество **0,1 XRP**, минимальный номинал открывающей заявки **5 USDT**. В расчёте лимитные цены Long округлены вниз до шага, количество округлено вниз до 0,1 XRP. Для минимального допустимого количества берётся максимум из 0,1 XRP и отношения минимального номинала к расчётной цене, округлённый вверх по шагу количества. Ценовые ограничения биржи зависят от типа заявки. В синтетических контрольных ценах отдельное ограничение диапазона цен не моделировалось. [Спецификация Bybit](https://bybit-exchange.github.io/docs/v5/market/instrument) · [Правила фьючерсов Bybit](https://www.bybit.com/en/help-center/article/Futures-Trading-Rules)

Для уровня с индексом `i` от 0 использован вес `(1 + мартингейл / 100) ** i`. Рассчитаны два допущения: геометрически растёт номинал в USDT либо геометрически растёт количество XRP. В первом случае номинал уровня пропорционален весу. Во втором он пропорционален весу, умноженному на цену уровня. В обоих случаях номиналы нормируются на общий лимит. Для повторения цены уровней считаются по формуле `первая цена × (1 − доля перекрытия × i / (количество − 1))`. Точная формула Veles остаётся неподтверждённой.

| Вариант | Перекрытие / мартингейл / ордеров | Ниже минимума при росте номинала | Ниже минимума при росте количества |
|---|---:|---:|---:|
| Агрессивный | 30% / 5% / 10 | 0 из 10 | 0 из 10 |
| Умеренный | 40% / 5% / 15 | 1 из 15 | 0 из 15 |
| Консервативный | 50% / 5% / 20 | 10 из 20 | 6 из 20 |
| Ручная сетка | 1% / 1% / 3 | 0 из 3 | 0 из 3 |

Количество заявок ниже минимума перепроверено независимым расчётом в целых лотах с точными дробями. Сравнение показывает, почему рост количества и рост номинала надо различать. По «Умеренному» нужен предпросмотр цен и количеств. Предыдущая модель из трёх равных ордеров использовала 0% мартингейла. Доступность 0% для XRPUSDT остаётся открытой. [Минимальная сумма Veles](https://help.veles.finance/ru/getting-started/pricing/minimum/)

## «Свой». Один ордер и схема 60/40

Один ордер на **100%** даёт в модели **105,0 XRP** по 1,0000 USDT. Для **60/40** при условном отсчёте от первого исполнения получено **63,0 XRP** по 1,0000 USDT и **42,1 XRP** по 0,9975 USDT. Номинал второго ордера после округления — **41,99475 USDT**, обе заявки проходят ограничения в модели. Контроль границы: на уровне 0,9975 USDT количество **5,0 XRP** стоит **4,98750 USDT**, поэтому минимальное количество на этом уровне — **5,1 XRP**. В редакторе нужно сверить подписи и базу отступа добавленной строки. [Режим «Свой»](https://help.veles.finance/ru/platform/settings/trading-mode/#режим-свой) · [Правила фьючерсов Bybit](https://www.bybit.com/en/help-center/article/Futures-Trading-Rules)

При первом ордере «Маркет» выбранные в форме 0,1% подтяжки остаются заполненным полем. По справке механизм подтяжки применяется к попытке с неисполненным первым лимитным ордером. [Настройки DCA](https://help.veles.finance/ru/platform/settings/full/#подтяжка-сетки-ордеров)

## «Сигнал». Условия и база отступа

В контроле Long задан минимальный отступ **1%**. Цена входа — **1,0000 USDT**, предыдущий исполненный ордер для примеров третьего — **0,9900 USDT**. Порог равен **0,9900 USDT** от первого или **0,9801 USDT** от предыдущего. Значение 1% выбрано, чтобы на третьем ордере явно различить базы. [Режим «Сигнал»](https://help.veles.finance/ru/platform/settings/trading-mode/#режим-сигнал)

| Контроль | Результат модели |
|---|---|
| Фильтр сработал при 0,9950, база — цена входа | Отступа недостаточно. |
| Фильтр не сработал при 0,9890, база — цена входа | Добор не отправляется. |
| Фильтр сработал при 0,9890, база — цена входа | Разрешена отправка рыночного добора. |
| Третий ордер, фильтр сработал при 0,9850, база — цена входа | Разрешена отправка рыночного добора. |
| Третий ордер, тот же фильтр и цена, база — предыдущий ордер | Отступа недостаточно. |
| Третий ордер, фильтр сработал при 0,9800, база — предыдущий ордер | Разрешена отправка рыночного добора. |

Прошли все шесть проверок условий. При подготовке настроек агент указывает фильтр и базу для конкретного ордера. В этом контроле проверена логика допуска по двум условиям. Цена исполнения рыночной заявки и точный момент повторной проверки фильтра остаются открытыми. [Режимы торговли](https://help.veles.finance/ru/platform/settings/trading-mode/)

## Совместимость с входом после ретеста

Проверено **19** исторических точек с 01.04.2026 по 23.11.2026 по тем же свечам и правилу пробоя и ретеста, что и в проверке тейк-профита. Для каждой точки первая цена взята с открытия следующей свечи 1ч с модельным проскальзыванием 0,03% и округлением по шагу цены. Стоп расположен на шаг ниже минимума ретеста. Максимальная дистанция до него от входа — **10,347%**. Последний уровень каждого из трёх пресетов оказался ниже стопа во всех 19 случаях. Ручная сетка 1% выходила за стоп в 12 из 19 случаев. При сохранении такой защиты дальние ордера широких пресетов располагаются за границей отмены сценария. [Исторический вход для воспроизведения](xrpusdt-veles-take-profit-review.md#историческое-воспроизведение) · [Свечи Bybit](https://bybit-exchange.github.io/docs/v5/market/kline)

В проверке сравнивалась реализуемость заявок и совместимость с уровнем стопа. Чтобы сравнить доходность, параметры входа и выхода должны быть сопоставимы, а уровни и объёмы подтверждены предпросмотром. Для добора на 0,25% Veles рекомендует тиковые данные. Обычный биржевой процентный стоп в Veles на Bybit ставится после исполнения последнего ордера. Поэтому проверка защиты с первого исполнения важна отдельно от проверки размеров сетки.
