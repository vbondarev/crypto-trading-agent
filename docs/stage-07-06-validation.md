## 1. Основания и реализованная область

Основные нормы: [FR-041–FR-046](requirements.md), [FR-001–FR-017](requirements.md), [FR-018–FR-026](requirements.md), [FR-027–FR-040](risk-management.md), [FR-047/050/052](requirements.md), [AD-009](data-freshness.md), [план 07](stage-07-plan.md), [контракт Skills](stage-07-skills-contract.md). Фактические соседние инструкции: [Data Verification](../.agents/skills/data-verification/SKILL.md), [Market Analysis](../.agents/skills/market-analysis/SKILL.md), [Portfolio Analysis](../.agents/skills/portfolio-analysis/SKILL.md), [Risk Assessment](../.agents/skills/risk-assessment/SKILL.md).

**Структура:** `SKILL.md` с простым YAML `name: strategy-planning` и `description`, явными положительными/отрицательными триггерами, 14 внутренними относительными ссылками, трассировкой требований и запретом самостоятельной торговли/готовности/выбора платформы.

**Назначение:** выбор *условных вариантов* `NEW LONG / NEW SHORT / ADD / HOLD / WAIT / REDUCE / CLOSE / RECOVER`, а не торговая конфигурация Veles/GinArea. Критичные R3-решения требуют реального аккаунта Bybit USDT Perpetual и всей цепочки проверки данных, портфеля, риска и выбранной формы P02. Состояния риска S0–S3 и FR не ослаблены из-за желаемой доходности или восстановления убытка.

| FR | Реализованное правило | Ограничение |
|---|---|---|
| FR-041 | Цель (новая позиция, управление, RECOVER, REDUCE), направление, бюджет, горизонт без вымышленных предпочтений | Нет принудительного T02/P02 для обучения/R1 |
| FR-042 | Сравнение существенных NEW/ADD/HOLD/WAIT/REDUCE/CLOSE/RECOVER с плюсами/минусами, отменой идеи и отклонёнными вариантами | Нет фиктивной доходности/вероятности |
| FR-043 | Прослеживаемое объяснение направления, рынка, условий входа/выхода и актуальных источников | Не придумывать конкретные уровни при отсутствующей закрытой OHLCV |
| FR-044 | Привязка к горизонту, бюджету, всем ботам и будущим ордерам с полным risk gate | RV-02/RV-03, реальные Mark/T02, FR-038, F/A/H/R не подтверждены |
| FR-045 | Net PnL связанной H01 серии, комиссии/funding один раз, recovery target с будущими расходами | Без execution/owner history нет доказанного `RECOVERED` |
| FR-046 | Два осознанных решения: пользователь выбирает стратегию; при боте отдельно выбирает Veles **или** GinArea | Само принятие документа 07.6 не является согласием на сделку/бот |

### Важные отрицательные правила

- Подтверждённая активная H04, достигнутые 3% дневного убытка либо 15% HWM DD запрещают **новый риск**, в том числе `NEW`, `ADD`, `RECOVER_WITH_ADD`. `REDUCE` или `CLOSE` обсуждаются как отдельные ручные потенциально снижающие риск действия; автоматических заявок нет.
- `WAIT` при уже открытой Cross/Short позиции не означает отсутствия риска. `HOLD` требует фактической позиции; `BUY` против One-Way Short может **сократить или развернуть Short**, не автоматически открыть Hedge Long.
- Для полного восстановления последовательности `net_now=−15+10−1−2=−8 USDT` недостаточно показывать +10 нереализованной прибыли. Условно нужно **ещё +8 net**; при дополнительных комиссиях 2 → **+10 price-PnL**, без новых неопределённых расходов. Эти числа **синтетические** и не являются реальной ценой входа/выхода.
- Отсутствие истории Equity H02/H03 само по себе помечается `NOT_CHECKED`, но **известную H04 игнорировать нельзя**. Для реального FR-038 обязательна историческая серия цен Bybit Mark по полной методике, а не четыре вымышленных траектории.
- Финальное решение о конфигурации **не выполняется** в Strategy Skill. Сначала отдельный выбор пользователя, затем актуальные T02/Mark и P02, потом соответствующий 07.7 либо 07.8 Skill **только когда тот создан и отдельно разрешён**.
