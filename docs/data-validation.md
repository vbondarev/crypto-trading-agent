# Протокол проверки доступа к данным — этап 04.3

> **Статус: ШАГ 04.3 ОТКРЫТ; РЕЗУЛЬТАТЫ ПРОВЕРОК И РЕЗЕРВНОГО ТЕКСТОВОГО МАРШРУТА НА СОГЛАСОВАНИИ (14.10.2026).** Выполнены реальные обращения к публичным страницам и API, дополнительные пробы альтернатив, а также отдельные проверки **синтетического структурированного текстового пакета**. Это **не подтверждает** стабильный веб-доступ, извлечение из реальных файлов/скриншотов или соблюдение риска. Приватные данные пользователя и платные подключения не проверялись. Протокол **не** означает завершение 04.3–04.8.

Основание: [согласованная матрица, каталог из 20 групп](data-sources.md), [план этапа 04](stage-04-plan.md), FR-007–FR-011, FR-018, FR-026, FR-028, FR-035, FR-040, FR-050 и FR-052.

## 1. Методика и критерии

- **Среда:** веб-поиск и чтение открытых URL в ChatGPT, без отдельного исполняемого HTTP-клиента, собственного сервера, API-ключей, авторизации, подписок и фонового мониторинга.
- **Дата испытаний:** **2026-10-14**; время в минутах/секундах для каждого запроса не фиксировалось надёжным журналом и **не выдумывается**. Время чтения страницы **не считается** временем биржевого наблюдения значения. Этим тестом **не устанавливаются** сроки свежести RV-05.
- **Контрольный инструмент:** `BTCUSDT`, **Bybit USDT Perpetual**, запрашиваемая категория `linear`. Тестовый инструмент не означает чтение реальных позиций пользователя. Для свечей тестировался `interval=60` (`1h`) и `limit=5`; остальные 15m/4h/1d **не подтверждены**, когда базовый endpoint не дал данные.
- **`VERIFIED_ACCESS`** — в этой сессии удалось прочесть **реальное** значение нужной категории вместе с достаточной информацией о его предмете, периоде/времени для соответствующего типа данных. **Указывается область подтверждения**, не весь источник.
- **`PARTIAL`** — страница/часть данных читается, но отсутствуют ключевые поля, точная дата, совпадение инструмента/рынка, числовой график или гарантии пригодности для исходной задачи.
- **`UNAVAILABLE`** — прямой тест указанных данных не дал их прочитать (включая HTTP 403/451, ошибку инструментов, пустую динамическую страницу); **не означает**, что сервис глобально не работает или у других пользователей нет доступа.
- **`NOT_TESTED`** — не было фактического теста соответствующего потока (авторизованные личные данные, скриншоты, конкретный токен-проект, все платные API).
- **`DOCUMENTED`** — подтверждено существование API/формата **из документации**, но **не** фактическое получение значений; эта пометка независима от четырёх статусов теста.

Если отдельные значения страницы отображаются как «today», «recently» или приблизительный относительный возраст, это **не полноценный timestamp** биржевой котировки. **Примеры ответа внутри документации API являются схемами, а не наблюдаемыми значениями рынка.**

## 5. Рекомендации для дальнейших шагов, без подмены решения

1. **Не объявлять `READY` при отсутствии проверенной биржевой Mark Price**, полной проверки счёта и расчётной модели ликвидации. Без них допускается только справочный/предварительный сценарий или запрос данных. Привычный вид торговой страницы и поисковые фрагменты **не заменяют** текущие данные.
2. **Прежде чем признавать решение о бесплатном автоматическом получении биржевых данных состоятельным**, нужно проверить альтернативные допустимые пути на 04.4/04.5 либо предложить пользователю **предоставлять свежие значения/выгрузки** для конкретной задачи. Источник может работать в ином браузерном окружении; этот результат не доказывает техническую невозможность доступа вообще.
3. **Формализовать RV-05 на 04.4:** различать `observed_at`, `published_at`, `retrieved_at` и `snapshot_at`; установить правила для цен, свечей, отчётов, соцпубликаций, динамической карты, личного портфеля.
4. **Проверить работу с пользовательскими материалами на 04.5/04.7:** синтетический текстовый снимок, скриншоты и выгрузки с соответствующими метками. Пока **не объявлять** успешным OCR/парсинг реальных файлов или реальный доступ к Bybit.
5. **Не выдавать выдачу поисковой системы за содержимое источника:** если поисковик показывает недавний заголовок, агент может сослаться на него с ограничением, но не утверждать, что просмотрел первичную статью и проверил её числа.
6. **Сохранить решение RV-01:** исторический HWM/дневная база необязательны; отсутствие полной истории Equity `NOT_CHECKED` не блокирует `READY` **само по себе**, однако это не ослабляет проверку текущего риска.

### 8.5. Минимальные сведения, которые пользователь должен предоставить при отсутствии API

**Сценарий M — анализ монеты без личного счёта.** Для выводов, основанных на реальных текущих данных: источник/биржа, точный `symbol`, тип `Bybit USDT Perpetual`, отдельно Last и при необходимости Mark/Index, единицы, `observed_at` и момент передачи/чтения. Для технического анализа — достаточно **длинная** история OHLCV **на нужных таймфреймах** с временем и единицами объёма. OI/funding/стакан/ликвидационные карты предоставляются, **если** они используются в ответе и не были подтверждены публичным способом. Нельзя заменять пропущенные интервалы придуманными RSI/EMA.

**Сценарий P — анализ текущей позиции или всего портфеля.** Дополнительно нужны `account.snapshot_at`, охват счёта, текущий Equity **с валютой оценки**, доступные средства, начальная/поддерживающая маржа, Cross/Isolated и One-Way/Hedge; **все** позиции с размером, направлением, средним входом, Mark, плечом, биржевой оценкой ликвидации (если есть), PnL; **все** активные, условные и потенциально открывающие позиции ордера и **все** боты/планируемые сетки. Пустые списки требуют **явного подтверждения полноты**. Несогласованные моменты снимков требуют уточнения.

**Сценарий B — проект и финальная проверка настройки Veles/GinArea.** Всё необходимое из P плюс платформа, выбранная пользователем стратегия, полный план IN/маржи/буферов, ограничения выхода/убытка, комиссии, funding, реальные поля и ограничения формы **со снимком итоговой заполненной формы**, повторное обновление данных непосредственно перед решением. Полноценные оценки Cross-ликвидации, риска Short, корреляций, четырёх стресс-сценариев — отдельные методики этапов 05–06. При отсутствии подтверждённых исходных данных/методик **`READY` невозможен**.

**История восстановления серии** (`H01`) нужна лишь при запросе расчёта её общего чистого результата. **Полная история Equity счёта** (`H02/H03`) необязательна по RV-01; при отсутствии — дополнительные исторические проверки `NOT_CHECKED` без заявления о соблюдении 15%/3%.

**Приватность:** использовать только данные, которые нужны текущему вопросу, передавать их непосредственно в личной беседе. Не просить API-ключи, пароль, UID счёта, доступ к кошельку; не помещать реальные снимки и финансовые числа в публичный GitHub.

### 8.6. Степень готовности резервного маршрута и следующие границы

- **Подтверждено для структуры:** извлечение полей из синтетического `key=value`, различение типов цены/единиц/времени, базовая арифметика, обнаружение отсутствующих критичных полей, сохранение RV-01.
- **Не подтверждено:** чтение **реального** API-ответа, скриншота, экспорта пользователя, полноты публичных данных, фактических лимитов биржи, корректной модели Cross или конечного риска Short. Два 1h бара не подтверждают полноценный технический анализ.
- **Решение о рабочем пользовательском шаблоне пока не принято:** на 04.5 следует отдельно утвердить удобную человеку форму текстового ввода/снимка/экспорта; не требовать ручного заполнения 40 категорий при каждом запросе.
- **04.3 остаётся открытым.** Без дополнительного одобрения **не переходить на 04.4** и не объявлять рыночные данные Bybit доступными через ChatGPT.
