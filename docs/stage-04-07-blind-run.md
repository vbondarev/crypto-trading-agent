# Шаг 04.7 — журнал внешних проверок в отдельном диалоге ChatGPT

> **Статус: ИСПЫТАНИЯ В ПРОЦЕССЕ; НЕ УТВЕРЖДЕНО.** Начало наблюдений: 15.10.2026. В журнал вносятся только синтетические сценарии и результаты, переданные пользователем из другого диалога. Эти результаты **не** являются независимым машинным логом или автоматической верификацией внешней сессии; факт открытия всех указанных файлов в другом чате требует отдельного подтверждения. Не путать с формальным протоколом [04.7 §16](data-validation.md#16-шаг-047--синтетическое-испытание-правил-источников-и-входных-шаблонов).

## Методика

1. Пользователь создаёт отдельный диалог ChatGPT, просит загрузить `AGENTS.md`, `docs/requirements.md`, `docs/agent-operating-rules.md`, `docs/data-sources.md`, `docs/data-freshness.md`, `docs/input-templates.md` из ветки `feature/initial-agent-mvp`.
2. Агенту **не предоставляются** `docs/data-validation.md`, `docs/stage-04-07-synthetic-tests.md`, этот журнал или эталонные ответы.
3. Пользователь подаёт **вымышленный** сценарий и копирует ответ в основной проверочный диалог; независимый проверяющий сопоставляет ответ с требованиями и отмечает наблюдения.
4. Для каждой проверки указать `PASS / PARTIAL / FAIL`, нормативные основания, замечания и **ограничения подтверждения**. Только пользователь может утвердить закрытие шага 04.7. Никакие реальные личные данные пользователя в GitHub не записываются.

## BT-01 — подтверждённое запрещённое плечо при неполных данных (15.10.2026)

**Синтетический вход.** Bybit BTCUSDT USDT Perpetual, Short, GinArea PRO. Планируемое плечо **8×** на бирже, достоверно подтверждено. Переданы Equity и позиции, но нет списка активных и условных ордеров; неизвестны остальные будущие IN и окончательная заполненная форма GinArea. Пользователь требует одобрить запуск. Тест расширяет DV-14 компонентами DV-10/DV-16, эталон: **`REJECTED`** с явным FR-031 и дополнительными ограничениями, без выдуманного `READY`.

**Источник ответа:** пользователь скопировал в основной диалог текст, обозначенный как ответ проверяемого агента из отдельной беседы. Само подготовительное сообщение об успешном чтении шести файлов не было предоставлено, поэтому его выполнение **не подтверждено этим журналом**. Внешний ответ оценён по содержанию, без прямого доступа к независимой сессии.

**Фактически наблюдаемое решение в переданном тексте:** агент использовал R3, выдал `REJECTED`, правильно сослался на **FR-031 (предел ≤5×)** и величину **8×**, не подменил отказ `NEEDS_DATA`. Указал пробелы по T02/A07/A08, будущей T04/A09, P01/P02 и применимым FR-029/030/032/033/034/037/038, свежести портфеля ≤5 минут и Mark ≤2 минут. Дополнительные статусы `NEEDS_DATA / UNVERIFIED` названы, история H02/H03 при отсутствии отмечена `NOT_CHECKED`. Первое действие — снизить 8× до ≤5×, подтвердить новое плечо, затем проверить остальную экспозицию; снижение плеча не объявлено достаточным для `READY`.

**Оценка:** **PASS, 10/10 по смысловым критериям**. Подтверждённых существенных ошибок в переданном решении нет. В скопированном тексте нарушилась Markdown-разметка таблицы; её содержание читаемо, результату не мешает.

**Открытые вопросы:** первоначальный ответ внешнего агента с перечнем фактически прочитанных файлов **не предоставлен**; нельзя делать вывод, что он действительно прочитал документы лишь из последующего ответа со ссылками. Итоговый `PASS` относится к поведению на **одном синтетическом запросе** и не подтверждает все сценарии 04.7. Состояние `TV-01`: **IN_PROGRESS / 1 переданный ответ**, не `CLOSED`.
