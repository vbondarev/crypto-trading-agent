> **Статус 05.7: `COMPLETED / APPROVED` (принят пользователем 15.10.2026).** Протокол проверяет [§14–§15 методики](risk-management.md#14-исторические-лимиты-equity-дневной-риск-и-блокировки-шаг-057). Ни реальные данные Equity, ни выписки/переводы/открытые позиции пользователя не запрашивались; весь набор — **вымышленный**. **05.8 — NOT STARTED**.

## 1. Контрольная область и базовые правила

**FR-028:** текущий риск обязателен, H02/Equity HWM с 15%-ной просадкой — **только при достоверной истории**. **FR-035:** дневной убыток ≥3% на базе **00:00 Europe/Moscow**, H03 проверяется **при наличии подтверждённых начальных данных и денежных потоков**. **FR-036:** достоверно известный активный H04 **всегда блокирует новое увеличение риска** до выполнения условий; для HWM после нормализации нужно **отдельное прямое согласование** пользователя. **FR-039:** сокращение риска отдельно разрешённое направление. **FR-040/050/052:** полный текущий/планируемый риск, обновлённый T02 и подтверждённая P02 форма обязательны для будущего READY; **05.7 сам по себе не даёт READY**.

Подтверждены ранее принятые правила [04.6](data-freshness.md#114-итоговые-статусы-и-приоритет-при-нескольких-проблемах), [T06/H02/H03/H04](input-templates.md#7-t06--необязательная-история-equity-и-известные-нарушения), [FR-028/035/036](requirements.md). **H01 связанной сделки не равна историческому Equity H02/H03**. История **рыночных Mark** для исторического стресс-теста [05.6](risk-05-06-validation.md) отдельна от истории Equity.

**Особый предлагаемый для приёмки выбор 05.7:** дневная база `B_day=min(B0,B0+net_external_flow)`. Это **проектная консервативная политика**, не опубликованная формула Bybit. Она не позволяет в середине суток размыть 3%-ный лимит новым пополнением и уменьшается после чистого вывода. При неприменимости/неполноте денежных потоков не объявлять эту величину подтверждённой.

**Метод локальных проверок:** 48 детерминированных арифметических/логических проверок `J01–J48` реально выполнены в изолированной JavaScript-среде, `Number` (IEEE 754 double), абсолютный допуск `1e-8` для числовых результатов и точное сравнение строк/булевых значений. Временные сопоставления проверены для **московской зоны UTC+3 на заданных датах**, результат не является универсальным тестом календарной библиотеки. Простые булевы предикаты **не** проверяют полную конечную машину H04; в production нужны Decimal, явное хранение событий и корректная библиотека часовых поясов. Независимых LLM-тестов **не** проводилось.

## 3. Стрессовые случаи и границы решений

**Порог ровно 15%/3%.** HWM 1000 → Equity850: **15%**, блокировка по FR-036 возникает при достижении порога. Дневная база B0=1000 с пополнением +500 и Equity1470: скорректированный net PnL **−30**, проектная база **1000**, дневной убыток **3%**, то есть блокировка. Наивный расчёт `(1000−1470)` ошибочно представил бы результат как прибыль. При выводе −200 и Equity776: net PnL **−24**, база **800**, снова **3%**. Ни перевод, ни вывод сами по себе не являются торговым PnL.

**H04 сильнее неполноты.** При подтверждённом историческом запрете агент сообщает `REJECTED` для **нового увеличения** даже без текущей T06/H02/H03. После следующего 00:00 МСК дневная блокировка проверяется на нормализацию по **свежему T02**; историческая остаётся до **явного подтверждения пользователя** плюс нормализации. Открывающий хедж или усреднение **не считается автоматическим снижением риска**.

**Отсутствующие сведения.** Если H02/H03 не предоставлены, обе дополнительные проверки получают `NOT_CHECKED`, а не `PASSED`. При этом недоказанная Cross/Short ликвидация остаётся `UNVERIFIED`, отсутствующий полный T02 — `NEEDS_DATA`, доказанное нарушение — `REJECTED` для увеличения риска. В рамках 05.7 никаких условий реального `READY` не выполнено.

## 4. Нормативная матрица Y01–Y34

В [§15.3](risk-management.md#153-синтетические-нормативные-сценарии-y01y34) описаны **34 документальных эталона Y01–Y34**: недостаточные исторические данные, вывод/пополнение, пороги, несовпадающие валюты, обновление T02, нераскрытый H04, разблокировка, историческая Mark-ветвь 05.6. **34 кейса не были 34 отдельными тестами ChatGPT.** J01–J48 исполняют **часть вычислительных и логических оснований**, а не комплексное исполнение каждого Y.
