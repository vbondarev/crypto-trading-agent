### 2.1. Принципиальные ограничения тестовой модели

1. Базовая фикстура — **одна вымышленная AAAUSDT Short-позиция с двумя IN**. Четыре цены S1–S4 — **четыре учебных пути одной пары**, а **не** четыре полноценных протокола F/V/H/R 05.6; multi-symbol correlation, FX stresses, funding dynamics, liquidity execution и реальные исторические Mark не моделируются.
2. Начальные `IM=100 USD`, каждый будущий `imUsd=20`, `FX USD/USDT=1`, `mmr` по четырём путям и `crossModel/shortBound=true` **явно искусственные входные флаги**. Они введены для проверки отдельных ветвей алгоритма; не получены из Bybit и **не означают** существование доказанной Cross модели или конечного worst-case Short bound.
3. Проверки `FR030_BOT_LOSS` в тестовом модуле относятся к **единственному синтетическому боту/позиции** в базовой модели. Для **нескольких разных ботов** нужно выделять PnL и убыток **каждого владельца**, а также отдельно совокупные co-loss портфельные сценарии; наивное присвоение всей потери каждому боту **некорректно**. Модуль этого разделения **не реализует** и не должен использоваться для торгового решения.
4. Модуль принимает искусственную цену исполнения по указанному в fixture `fillIds`; корректную рыночную последовательность/ликвидность/latency не доказывает. При фактическом превышении согласованного риска в реальной позиции вывод зависит от реально подтверждённых данных и применимости сценария, а не от этой игрушечной котировки.
5. `positionIdx` и биржевой owner должны быть доказаны. Уникализация по `account/symbol/slot/orderId` полезна для учёта **доказанных** ID, но при неизвестном orderId нужна ручная трассировка, не эвристика по совпадающим price/qty.
6. Для FR-032 Cross доказанную модель нельзя заменить справочной `position.liqPrice`; Bybit показывает динамическую оценку при Cross, а закрытие по риску UTA зависит от account MMR, порог 100%. Portfolio Margin/Isolated нужно проверять отдельно.
7. `LOCAL_POLICY_PASS_NOT_READY` — **служебный результат внутри локального теста**, а не пятый пользовательский торговый статус. Успех арифметики не равен успешной P02/Bybit проверке. Фактические пользовательские статусы остаются `READY / NEEDS_DATA / UNVERIFIED / REJECTED`.
