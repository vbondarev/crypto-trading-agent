## 2. Что именно проверяется на полном портфеле

| Зона | S0: факт | S1: будущее | S2: после fill | S3: риск / статус |
|---|---|---|---|---|

**Приоритет итоговых статусов для нового риска:** `REJECTED` при доказанном нарушении применимого строгого лимита; `UNVERIFIED` при неразрешённом конфликте или незавершённой критичной модели (например, RV-02/RV-03); `NEEDS_DATA` при неполных обязательных входах без более сильного обнаруженного запрета. `READY` возможен **лишь в реальном рабочем процессе с подтверждёнными R3/T02/P02/стрессами**; локальный JS-вывод `LOCAL_POLICY_PASS_NOT_READY` не является пятым статусом агента.

### 2.1. Правило пересчёта заказа без двойного счёта

**Идентичность order:** `(account, symbol, positionIdx, exchangeOrderId)` только если эти поля подтверждены. Один биржевой ID, показанный Veles и T04, — одно обязательство. Разные ID на одинаковых цене и количестве — **разные** заявки. Без ID не склеивать наугад; значимый `POSSIBLE_DUPLICATE` оставляет `UNVERIFIED`.

**Margin:** `IM_projected = IM_account_already_occupied + incremental_future_IM_not_yet_in_baseline + fees/collateral_buffer`. Уже отражённую в UTA occupied IM повторно не добавлять. Но для **FR-034** документировать полную потребность/финансирование **всех** допустимых будущих IN, включая ещё не занявшие IM условные заявки. Реальный UTA Cross IM не рассчитывать одной формулой `notional/leverage`; коэффициенты and account haircuts различаются по валютам и tier. Локальная имитация test-harness **принимает IM по каждому уровню как заданный вымышленный вход**, а не вычисляет её по реальной биржевой методике.

**Событийность:** исполнение IN/OUT, partial fills, отмена/восстановление, bot restart, P02 edit, Veles изменённое плечо, GinArea Disable/Pause, manual Bybit и другие боты аннулируют прежний T02/P02/ownership для R3, независимо от остатка 5 минут; Mark TTL ≤2 минуты или строже по AD-009.

### 3.1. Демонстрационный портфель (вымышленный)

`E0=1000 USD; baseline IM=100 USD; margin buffer=10 USD; fxUSDperUSDT=1 (ИСКЛЮЧИТЕЛЬНО учебная гипотеза)`. Есть `AAAUSDT` Short qty 2 при Mark100, открытый будущий IN `i1` qty1@110 с IM20 **уже входящим в базовую IM**, виртуальный `i2` qty1@120 с IM20 ещё **не** в базовой IM. Текущий Side/slot: `Sell/positionIdx=2` как синтетический Hedge пример; есть 1 биржевой слот.

`IM_projected=100 + 20(только i2) + 10(buffer) =130 USD = 13% E0`, `full_future_required=20(i1)+20(i2)+10(future buffer)=50 USD`; это **две разные величины**, не складывать обе с одинаковой целью. Для условного резерва тестовый budget100 USD покрывает 50 USD будущих обязательств. Значения `imUsd` заданы, не выведены реальной функцией Bybit.

| Локальный тестовый путь | Синтетическое условие и результат | Ограничение |
|---|---|---|
| `S1_ADVERSE_UP` | Mark AAA104, без fill; цена выше на 4, убыток `2×4+3(cost)=11 USD` | Не заменяет полную F-матрицу |
| `S2_ALL_IN` | Mark AAA110, оба будущих IN *предположены исполненными* по 110 и 120; Gross short loss `2×10 +1×0−1×10=10`, +3 costs → **13 USD** | Это гипотетический путь с прошлым достижением 120 и откатом к 110, **не** алгоритм реального fill |
| `S3_GAP` | Mark AAA112, без fill, costs5 → `2×12+5=29 USD` | Не показывает неограниченный worst-case Short, стоп не гарантирует цену |
| `S4_OTHER_COSTS` | Mark AAA105, fill i1 по 110, costs7 → `2×5−1×5+7=12 USD` | Финансирование/realized PnL в живом аккаунте не проверены |

**Максимум по этим четырём учебным путям 29 USD / 2.9% E0. Это НЕ максимальный возможный убыток Short и НЕ прохождение FR-030/038.** Если в синтетическом сценарии `S3` задать Mark 128, `2×28+5=61 USD=6.1% E0`: модель отвергает такую **условно обязательную** стресс-ветвь. На реальном рынке это не доказанное нарушение без применимости и подлинных данных (см. 05.5).

**Семантика статуса в тестах:** проверка `status=REJECTED` означает, что *для предложенной модели и выбранного применимого синтетического ограничения* найдено нарушение; `UNVERIFIED` — нет доказуемой модели; `NEEDS_DATA` — нет поля. Стрессовые величины **не доказывают live-loss**. Симулированный флаг `evidence.cross=true` и `evidence.shortBound=true` нужен для отдельных ветвей без блокирующего `UNVERIFIED`; это **не** заключение о наличии такой модели в Bybit.

## 4. Обязательные стресс-семейства F/V/H/R — отдельный протокол (НЕ выполнен на реальных данных)

Этап [05.6](../risk-management.md#12-корреляция-и-стресс-тестирование-всего-портфеля-шаг-056) закрепил четыре **содержательно разных**, а не четыре произвольных ценовых пути протокола:

| Протокол | Минимальные данные и логика | Реальное состояние на 06.7 |
|---|---|---|
| **F — Fixed shocks** | Для **каждого** инструмента ±5/±10/±15/±30% по Mark, одновременные co-loss Short↑/Long↓ и полные IN/OUT, fees/funding, FX | **PARTIAL_SYNTHETIC_ONLY**: четыре учебных пути одной пары AAAUSDT, не полная F-сетка и не настоящий портфель |
| **V — Volatility/liquidity** | Доказанные волатильность, изменение ликвидности, проскальзывание/гэпы/частичное исполнение и задержки по каждому инструменту | **NOT_CHECKED / NEEDS_DATA**, данных ликвидности/real slippage нет |
| **H — Historical market stress** | Проверенные синхронные исторические Mark-цены, временной охват и источники, реконструкция динамики портфеля | **NOT_CHECKED / NEEDS_DATA**, исторических рядов цен нет; не путать с необязательной историей Equity H02/H03 |
| **R — Reverse stress** | Найти минимальный adverse path/набор событий до hard limits, MMR100%, непокрытого IM, невыполненного стопа/невозможности исполнения | **PARTIAL_SYNTHETIC_ONLY / UNVERIFIED**: есть отрицательные пороговые примеры, но нет полной обратной оптимизации и биржевой MMR |

**Следствие:** FR-038 **не подтверждён**, даже если локальная модель показывает все 57/57 PASS. Для реального R3 требуется F/V/H/R по полному реальному портфелю либо отдельное изменение согласованных требований с явным разрешением пользователя; такой пересмотр **не выполнялся**. Отсутствие H02/H03 означает `NOT_CHECKED` только для исторической Equity-проверки и само по себе не блокирует READY, **но отсутствие исторических Mark-данных не позволяет объявить протокол H исполненным**.

## 7. Дополнение по итогам ревизии 06.8 — 16.10.2026

Первоначальные **57/57 локальных проверок 06.7** были приняты пользователем в обозначенных документальных границах. В ходе независимого **повторного чтения исходного кода этим же ассистентом** обнаружены недостающие ветви: заявка `FILLED` ошибочно учитывалась как будущий IN, возможные новые биржевые слоты при будущих IN не участвовали в лимите FR-033, а `orderId=undefined` и неизвестный `purpose` не маркировались как недоказанные. Исправлены предикаты, добавлены регрессионные **R58–R64, полный повторный запуск сохранённого исходного кода — 64/64 PASS** ([доказательная запись](../stage-06-review.md)). Эти исправления **не делают модель реальной Bybit/Cross-системой**. Сохраняются FR-038 и RV/TV.
