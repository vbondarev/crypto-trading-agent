## 1. Область, версии и реестр доказательств

**Рынок в области:** GinArea → Bybit → `USDT Futures` (линейные USDT-контракты), направление `Long/Short`, Bybit `Unified Trading Account`. **Счёт и режим маржи должны быть подтверждены до выдачи конфигурации.** Документация GinArea для Bybit требует UTA, Cross Margin, One-Way; исключение: для `Default Grid` документирована возможность Hedge. **Это ограничения из справки, а не доказательство реальной формы/позиционного режима пользователя**. Spot, COIN Futures, другие биржи сюда не переносить.

**Происхождение:** все свидетельства `G-01–G-14` — официальная публичная документация, просмотренная **16.10.2026**, `evidence_class=D1/OFFICIAL_DOC; documentation_observed_at=2026-10-16; published_at=UNKNOWN; platform_build=UNKNOWN; user_ui_observed=false`. Ниже **`DOCUMENTED_FOR_SCOPE` означает только сведения справки**, не подтверждённые параметры личного PRO. Тариф, план, язык интерфейса, условия раскрытия вкладок, значения `min/max/default` личной формы и право редактирования проверяются отдельно, без догадок.

## 2. Матрица P01: тип рынка × стратегия × биржевой режим

Режимы `Hedge/One-Way` и `Cross/Isolated` — **факты текущего аккаунта Bybit**, не свободные поля во всех вариантах редактора GinArea. Для отдельного `symbol` обязателен фактический **selector GinArea** и подтверждённые биржевые ограничения по qty, step, price tick.

| Код | Стратегия при USDT Futures | Публично подтверждённая возможность | Ограничение, без которого нельзя рекомендовать |
|---|---|---|---|
| C-G01 | **Default Grid** | Одно направление Long **или** Short; документально допускается One-Way или Hedge | Bybit UTA/Cross по G-02; фактический Hedge, пара и версия P02 неизвестны |
| C-G02 | **Auto Grid** | Алгоритм может открывать Long/Short; в G-11 указаны One-Way **и Cross** | Hedge/Isolated для этого варианта — `DOCUMENTED_RESTRICTION`. Long/Short бота в статистике ≠ отдельные биржевые позиции |
| C-G03 | **Dynamic Grid / Dynamic Auto** | Динамические границы и направления Long/Short/Auto, **PRO only** | One-Way для non-Default по G-02; Cross — требование общего раздела Bybit; точная пользовательская поддержка неизвестна |
| C-G04 | **Indicator Grid** | Условия по EMA/RSI/MA/SMMA/ATR/Supertrend и др.; документально есть USDT Futures | One-Way для non-Default, Bybit Cross из G-02; **доступность выбранной пары не доказана** справкой |
| C-G05 | **DCA** | Периодические IN фиксированного размера; семейство в G-03 | Не приписывать DCA специфические грид-поля или индикаторы; фактическая P02 обязательна |
| C-G06 | **Любая non-Default + подтверждённый Hedge** | G-02 явно ограничивает режим | `DOCUMENTED_RESTRICTION` → `REJECTED` для запуска в этой несовместимой комбинации |
| C-G07 | **Любая из вышеуказанных + подтверждённый Isolated на Bybit** | G-02 указывает Cross как требование Bybit | В рамках **документальной инструкции** не считать эту конфигурацию совместимой; если другой официальный источник/форма возражает — `CONFLICT/UNVERIFIED`, не придумывать поддержку |
| C-G08 | **Spot/COIN Futures**, даже при общем названии поля | Вне данного контракта `USDT Futures` | `REJECTED` для задачи, в которой запрошен Bybit USDT perpetual; не переносить валюту залога |
| C-G09 | **Auto Grid/Dynamic Auto** с двумя внутренними направлениями | Один One-Way биржевой net-position может менять направление | Расчёт T02/FR-033 по **фактическому биржевому слоту**, а незакрытые IN каждого направления учитывать как обязательства |
| C-G10 | **Любая стратегия + не подтверждённый symbol или PRO-форма** | Общая доступность семейства описана | Конкретная конфигурация `NEEDS_DATA/UNVERIFIED` до подтверждения пары/режима/версии и реальных полей |

**Не делать предположение, что пользовательская форма с названием “Indicator Grid” поддерживает GPS/FLOCK или любую другую пару.** Доступность пары/режима должна иметь дату, источник и точную стратегию.

## 4. Единицы, сетка, множители и расхождения между справкой/биржей

1. **`Размер ордера` ≠ `Макс. размер` ≠ `Максимальный размер всей позиции`.** Первое — базовый отдельный IN; второе — потолок отдельного IN при росте; общий сценарный номинал требует просчитать **всю последовательность** с qty rounding, шагом, возможными повторными циклами и остановкой, включая другие боты и T02.
2. **Полностью вымышленный пример с единицей BTC:** `Размер=0.1 BTC, Мультипликатор=1.5, Макс=0.3 BTC` даёт необработанные уровни `0.1,0.15,0.225,0.3,... BTC` при отсутствии внешнего изменения серии. **Округление по lot/минимуму может уменьшить фактические значения.** Учитывать `floor(q/qtyStep)×qtyStep` как *упрощённую модель*, а не универсальную биржевую реализацию; `minQty, qtyStep, minNotional` индивидуальны по инструменту.
3. **Суммарный будущий номинал** не выводится из `Макс. размер` одной заявки; `∑(qty_i×price_i)`, с направлением/ценой/издержками для каждого допустимого сценария, после проверки единиц. Если `Размер` введён в USDT, это **номинал заявки**, не quantity монеты и не заложенная маржа.
4. **Множитель шага сетки** меняет расстояние между ценовыми уровнями; **Мультипликатор** меняет **размер IN**, это **разные** функции. В Auto Grid множитель размера по публичной справке сквозной по направлениям, в Dynamic Auto — отдельно на каждую сторону; умножение `Шаг×Количество` лишь грубо оценивает диапазон, не формирует точную сетку.
5. **% Режим** меняет единицы настроек входа/выхода; при выключении в справке абсолютные величины. Нельзя вводить `2` без контекста `2%`, `2 USDT` или `2 price units`.
6. **Плечо GinArea:** [официальный пример](https://help.ginarea.org/ru/botmanagement/levcalc/) вычисляет `L_bot=(Размер ордера×Количество ордеров)/Депозит` только для **фиксированной величины каждого IN**. При мультипликаторе, раздельных сторонах, повторных циклах и неизвестных ценах эта формула **не точная оценка** full future margin. Биржевое плечо, риск 05/FR-031, существующие позиции и возможный лимит UTA — проверять самостоятельно. Документальный пример с 20×/100× **не** разрешает агенту рекомендовать плечо >5×.
7. **Auto/Dynamic виртуальные стороны и One-Way:** статистика GinArea может показывать открытые Long/Short IN одновременно, но биржевой net-position может быть 0 или сменить направление; это **не 2 биржевых Hedge слота**. При этом потенциальные IN и закрывающие триггеры обеих сторон влияют на резерв и сценарии.
8. **Границы торгов/Disable IN:** эти настройки контролируют **новые IN**, не гарантируют ни нулевой позиции, ни закрытия старых ордеров, ни прекращения риска; выключение IN не доказывает отсутствие комиссий, funding или ликвидации.
9. **TP/SL/P&L-трейлинг:** по справке некоторые величины выражены в USDT результата, а другие в процентах движения или профита. Без явной базы не допускать смешения. `Стоп-Лосс` по финансовому результату бота **не гарантирует конечный верхний Short-loss ≤5% Equity**; RV-03 открыт.
10. **Стратегия и аккаунт:** выбранная `Cross`/One-Way и биржевой номинал реального инструмента **не** доказываются чтением справочной страницы. При противоречии P01/P02/Bybit `CONFLICT→UNVERIFIED`, при известном документальном запрете применимого режима `REJECTED` для нового рискованного запуска.

### 8.2. Четыре независимых слоя состояния

1. **Bot control (GinArea):** работает / `Disable-IN` / приостановлен / `Failed` / остановлен (условные аналитические классы; **не список точных enum UI**). Приостановка не доказывает нулевую биржевую позицию.
2. **Виртуальные триггеры:** потенциальный IN, созданный ботом IN, открытый ботом IN, ожидающий OUT/Out Stop, закрытый IN, накопленный P&L trailing. Это **нормализация**, не названия биржевых полей. Триггер не обязательно отдельный live Bybit orderId.
3. **Биржевая позиция:** фактические `(account,symbol,positionIdx,side,qty,entry,Mark,IM/MM)` из свежих T02/T03; в One-Way Long/Short внутри GinArea **неттируются** на одну биржевую позицию, которая может равняться нулю при оставшихся виртуальных триггерах.
4. **Владелец и портфель:** manual/GinArea/Veles/other bots, актуальные active/conditional orders и будущие IN; познавательная «позиция бота» **не обязана равняться** биржевой позиции, особенно при двух ботах на паре или ручном вмешательстве (G-21). При неизвестной трассировке биржевой orderId ↔ bot trigger ↔ T03 оставлять `POSSIBLE_DUPLICATE/CONFLICT`, а не суммировать точное количество.

Публичная статистика GinArea различает **Профит**, **Реализованный**, **Нереализованный** и **Total Current Profit**: источник отдельно отмечает **funding не включён** и `bot unrealized` ≠ `exchange UPL`. Поэтому ни один из этих показателей автоматически не является Net PnL всей связанной серии H01 или Equity всего T02. При анализе `FR-045` обязательно сохранять fee/funding, выводы от ручных сделок и реализованные потери.

### 8.3. IN и OUT: порядок операций, триггеры и частичное исполнение

- По G-17 **«Целевой уровень прибыли» — это достижение ценой триггера**, после которого бот выставляет/активирует закрывающий стоп на `Мин. Стоп`; **не** прямой факт прибыли и не биржевая гарантия исполнения по этой цене. `Мин. Стоп` пустой → документально 0, но фактический P02 проверить. `Макс. Стоп` — трейлинг OUT; в документации объединение Out Stops может закрывать отдельные IN с убытком.
- **«Выход по средней цене»** в G-17 агрегирует триггер относительно средней открытых IN, вместо независимого выхода каждого IN; **«Не ухудшать цену входа»** ограничивает новые IN относительно бот-средней Long/Short. Средняя GinArea не обязательно биржевая (другие боты/ручные изменения).
- **«Инстоп»** G-17: при отклонении и развороте может объединить **несколько пропущенных IN** в один крупный вход, а не создавать независимые рыночные IN на каждом уровне. Опция документирована для **Default и Dynamic**; **не переносить в Indicator Grid и DCA**. Получившийся номинал объединённого входа может кратно превосходить базовый `Размер ордера`; прежде чем заявлять, что `Макс. размер` ограничивает **весь** объединённый объём, требуется отдельное доказательство взаимодействия двух настроек.
- По G-18 **после закрытия всех IN множитель сбрасывается**; после частичного закрытия новый IN может повторить объём закрытого ордера, а не вернуться к базовому. При закрытии нескольких разных объёмов G-18 **не полностью задаёт точную очередность** следующих IN → для строгого прогноза требуется версия/P02 и подтверждённое поведение; без него `UNVERIFIED` по риску полной последовательности.
- **Partial fills в смысле биржевого qty** не имеют здесь подтверждённого автомата GinArea: моделировать `qty_filled+qty_leaves=qty_total` только по достоверным Bybit полям, `filled` → фактический S0/S2, `leaves` → S1, 0 исполнений из визуального триггера не выдумывать. Два разных orderId одинаковых price/qty **нельзя** склеивать, один подтверждённый orderId из T02/T04 считать один раз.
- **Режимы Auto Grid**: `Last Order PNL`, `Avg Price`, `Avg Price Inverse` выбирают сторону по **разным правилам** (G-27); нельзя объявить общий алгоритм `next direction` для всех. Биржевой One-Way может переворачиваться. Если две виртуальные стороны равны по объёму, биржевое `qty=0` **не** означает, что нет дальнейшего риска при срабатывании одного из IN/OUT.
- **Indicator Grid**: при выбранной функции `Условия выхода` выход может быть инициирован **при отрицательном PnL** (G-28), не только по TP. Необновлённые цена/индикатор/таймфрейм не подтверждают текущий signal; наличие стратегии в справке не доказывает её доступность для конкретной пары в PRO.

### 8.4. Disable IN: событие, причины, защёлка и восстановление

| Входное событие | Документально описанный переход | Что проверять на Bybit |
|---|---|---|
| Пользователь **включил Disable IN** | Запрет **новых** IN, уже открытые OUT-триггеры продолжают закрываться (G-15) | Текущие открытые позиции/ордеры остаются до подтверждённого изменения; неизвестно, какие уже переданные IN отменились |
| Цена вышла за заданный диапазон, настройка **«Активация Disable IN вне границ»** включена | Включается и **защёлкивается** Disable IN; **возврат внутрь не выключает его** (G-15/G-16) | `range` — ограничение новых IN, не автоматический SL/закрытие; правило ценового базиса для live UI проверить |
| Пользователь вручную **выключил Disable IN** | Новый IN снова **возможен** на свободных гридах (G-15) | Не создавать фиктивное исполнение: наличие средств, плеча, режима, пары и условия входа проверяются повторно |
| Бот показывает `Disable-IN` без явной ручной активации | G-24 перечисляет **нехватку маржи, предел плеча, выход за границы и скопированную настройку** | Причину установить по реальному статусу/логам, не считать безопасным просто снять флаг |
| Нет IN, но есть OUT, funding и маржа | Риск ликвидации/потерь сохраняется; запрет новых IN **не превращает** портфель в нулевой | FR-029/030/032/034, активные заявки, состояние T02/T03/T04 |

**Важно:** документ не доказывает, что уже отправленная на биржу заявка IN автоматически отменяется при переключении Disable IN. Пока фактическая отмена не подтверждена, такая заявка остаётся потенциальным исполнением. Поэтому нельзя объявить `Disable-IN ⇒ future risk = 0`.

### 8.5. Остановка, ручное вмешательство и Failed

**Справка G-20 описывает последовательность из двух действий:** поставить бота **на паузу**, затем выбрать **«Закрыть позицию»** в меню. Это **не** одно и то же. До подтверждённого биржевого исполнения команда закрытия только **запрос действия**, а не позиция `qty=0`. Для одиночного закрытия отдельного ордера документ G-22 требует сначала паузу, затем действие «×»; **это может изменить позицию бота, ордера и рассчитанные исходы**, нужен полный новый T02.

**Торговля вручную на бирже**: G-20 прямо предупреждает о нарушении алгоритма. G-23 указывает ручную биржевую торговлю одной из причин `Failed`. Если пользователь уже закрыл/увеличил позицию на Bybit, нельзя автоматически «подхватить» её как корректно контролируемую GinArea; не советовать одновременное ручное и автоматическое управление. Требуются остановка новых рискованных действий, реальная сверка T02/T03/T04 и **ручное решение пользователя**, а не бесконтрольное повторение IN/restart.

**Причины Failed (документальный перечень G-23):** недостаток обеспечения, ликвидация, ручная биржевая сделка, неподдерживаемый Hedge, недостижимый/некорректный профит-триггер. Статус `Failed` **не доказывает**, что биржевая позиция закрыта и больше нет ордеров. Restart/редактирование инвалидацируют P02 и T02 и могут возобновить IN; **не назначать автоматическое восстановление**. В условиях убытка/recovery `FR-051` требует определить собственника и конфликт по паре/режиму.

**TP/SL и финансовая цель:** G-19 привязывает TP/SL к профиту бота; «Обновление Тейк-Профита» может увеличивать цель и запускать следующий цикл. G-26 описывает отдельную **остановку по времени+профиту**, при которой авто-restart **запрещён даже при обновлении TP**. Не сводить эти функции к одному абстрактному стопу. `Stop Loss -100 USDT` — **триггер в логике бота**, но не математически доказанный максимум денежных потерь Short при разрывах котировок (RV-03). `P&L trailing` G-25 расходует часть ранее полученного профита на закрытие убыточных триггеров; реальный профит связанной серии может снизиться — H01 нужно обновлять.

### 8.7. Сопоставление со стадиями S0–S3 и риск-лимитами

- **S0:** полный Bybit T02/T03 с `Equity`, IM/MM, действительными One-Way/Hedge слотами, order IDs и датой. `position_bot` не заменяет exchange position. Подтвердить актуальную Mark и охват всех счетов.
- **S1:** все реально выставленные и условные заявки, виртуальные IN/OUT без идентификаторов и будущие обязательства из сеток всех ботов; чёткий `source/identity/quantity/unit`. Если Disable IN включён, по умолчанию **не удалять уже размещённые IN** без биржевого подтверждения; новые предполагаемые IN моделировать только по актуальной разрешённой ветви.
- **S2:** ветви исполнения, закрытия, Instop-объединения, повторного IN после partial close, разворота One-Way, restart и комиссии; `qty_filled` учесть 1 раз, `qty_leaves` оставить возможным риском.
- **S3:** adverse movement/stress для **всего** портфеля, Cross MMR, funding, gaps/slippage, неизвестный sequence при multiplier/loops, опасность повторного IN после ручного снятия Disable IN.

**Неподлежащие ослаблению ограничения FR-029–FR-040:** агрегатная маржа ≤30% Equity, доказуемый верхний убыток каждого бота ≤5% Equity, плечо ≤5×, adverse distance ≥15% до ликвидации, максимум 3 биржевых позиции, резерв **100% всех достижимых будущих IN + издержки**, четыре семейства стрессов и правило управления риском. **Число IN «Количество ордеров» может быть лимитом одновременно/в цикле**, но при повторных циклах и частичных OUT нельзя автоматически утверждать конечный суммарный lifetime notional или bounded loss без подтверждённого горизонта/ограничений. В противном случае `UNVERIFIED`, а не `READY`.

**Событийная свежесть AD-009:** Fill/partial fill, новая/отменённая заявка, Disable IN reset, pause/close, TP/SL change, restart, ручное вмешательство, изменение плеча/маржи, другой бот → **инвалидация** соответствующей части T02/T03/T04/P02 даже в пределах 5 минут. R3 требует весь T02 ≤5 минут и Mark ≤2 минут или строже в зависимости от волатильности. H02/H03 без истории `NOT_CHECKED`, подтверждённый H04 запрещает увеличение нового риска.
