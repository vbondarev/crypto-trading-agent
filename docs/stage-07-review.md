## 3. Реальные логические маршруты: RT01–RT10 и 17 учебных вариантов

**Эта таблица — утверждённая нормативная маршрутизация по подтверждённым документам, не доказанная автозагрузка в ChatGPT.**

| Маршрут | Задача | Нужная цепочка / ограничение |
|---|---|---|
| RT01 | Обучение, без текущих котировок | Обычный ответ без принудительного Skill, T02 или P02 |
| RT02 | Рынок R1 | `market-analysis`; при текущих ценах также `data-verification` |
| RT03 | Технический сценарий R2 | `data-verification → market-analysis → strategy-planning`; дополнить портфелем/риском **только при релевантной позиции и нагрузке** |
| RT04 | Аккаунт и ордера | `data-verification → portfolio-analysis → risk-assessment` |
| RT05 | Убыточная позиция/RECOVER | `data-verification → portfolio-analysis → risk-assessment → strategy-planning` + net H01/fees/funding |
| RT06 | Сравнение Veles/GinArea | `strategy-planning` + **справочные P01**, **без выбора платформы вместо пользователя** и без готовой P02 |
| RT07 | Выбран Veles | Проверка данных/полного портфеля/риска → при необходимости стратегия → **только** `veles-configuration` |
| RT08 | Выбрана GinArea | Аналогично, затем **только** `ginarea-configuration`; подтверждение пары в *конкретном* селекторе |
| RT09 | Финальный R3 | `data-verification → portfolio-analysis → risk-assessment → (veles-configuration ИЛИ ginarea-configuration)`; настоящие P02/T02/Mark и все FR обязательны |
| RT10 | Fill/edit/restart/смена маржи | AD-009 **инвалидирует** прежний портфель/риск/конфиг; повторные снимки, затронутая платформа |

В 17 синтетических комбинациях проверялись R1 без T02, R1 с текущей ценой, R2 с/без позиции, recovery, сравнение до выбора, обе платформы в R2/R3, отсутствие выбора и повторный аудит после события. Для одного запроса **обе конфигурационные ветви не используются одновременно**, маршрут не дублирует модуль и не подставляет неподтверждённый `main` вместо feature-ветки.

**Технический контракт реального использования:** при вызове нужно проверить фактическое чтение соответствующего `SKILL.md` из указанной ветки/commit, передать источники/единицы/observed_at/snapshot_id и указать `body_read=TRUE/FALSE`; если нет доступа — `NOT_LOADED` и ограниченный вывод. Наличие файлов в репозитории **не означает** установку Skills в обычном чате ChatGPT или автоматическое выполнение маршрута.

## 4. Сквозные инварианты — ограничения сохранены

| Инвариант | Ревизионное решение |
|---|---|
| **FR-029** | Максимальная достигаемая полная IM текущих и будущих позиций/ботов **≤30% текущей полной Equity**, без повторного включения уже занятой IM |
| **FR-030** | Доказанный **worst net loss одного бота ≤5% Equity**; цена обычного SL или синтетический шок **не доказывают** конечный Short loss (RV-03) |
| **FR-031** | Плечо **≤5×**, включая невалидность предлагаемых 8× и документально приведённых чужих примеров |
| **FR-032** | Надёжная adverse distance **≥15% от Bybit Mark** до ликвидации; показанная `liqPrice` при UTA Cross не доказывает account-wide MMR (RV-02) |
| **FR-033** | **≤3 потенциальных биржевых слота**, включая будущий IN на другом symbol и отдельные подтверждённые Hedge sides |
| **FR-034** | **100% reserve** маржи всех достижимых будущих IN + costs/funding/slippage, не только уже выставленные ордера |
| **FR-035/036** | Дневная **3%** блокировка от МСК 00:00, historical HWM **15%** и известный **H04** запрещают новую нагрузку; H02/H03 без Equity history `NOT_CHECKED`, а не автоматически `REJECTED` |
| **FR-037/038/040** | Co-loss всего портфеля и **четыре F/A/H/R**; реальный H требует датированных **Bybit Mark-market**, а не синтетических price paths; нет полноты — нет `READY` |
| **AD-009** | Для R3 T02 ≤5 минут, Mark ≤2 минут с ужесточением по ситуации; fill/order/edit/restart/Disable reset/маржа меняют действительность снимка независимо от TTL |
| **FR-047–FR-053** | **Только выбранная пользователем платформа и текущая P02**, exact pair/strategy/units, validated Bybit minQty/qtyStep/tickSize; платформенные значения не взаимозаменяемы |

Нормативные **причины окончательного решения:** доказанный hard limit → `REJECTED` (даже при недостающей P02), конфликт источников/моделей → `UNVERIFIED`, отсутствующие обязательные данные → `NEEDS_DATA`. Состояния `NOT_CHECKED`, `LOCAL_PASS_NOT_READY`, `DOCUMENTARY` — только внутренние квалификации, **не пятый статус торговли**. `READY` только при реальном доказательстве всего требуемого R3; ни один локальный PASS его не подтверждает.

В примечании-erratum сохранена историческая строка для объяснения исправления, а не как действующая норма.

**AUD-07-02 — ложноположительное срабатывание нового composition test:** первое исполнение дало **141/142** потому что тест принимал историческую цитату `F/V/H/R` в erratum за актуальную норму. Исправлен *тест*, проверяющий только действующий раздел до erratum; сохранённый тест заново прочитан и исполнен **142/142 PASS**. Риск-алгоритмы не менялись.

**Ревизия не обнаружила новых подтверждённых конфликтов в маршруте** Veles/GinArea, hard-limit-veto, owner/orderId, H01, AD-009 после указанных исправлений **в границах текстового анализа и упрощённых механических предикатов**. Этот вывод **не** означает доказанного отсутствия конфликтов в независимом запуске модели или на настоящих Bybit/GinArea/Veles версиях.
