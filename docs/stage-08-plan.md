Пользователь остаётся инициатором каждого существенного шага и выбора; один пользовательский запрос **не активирует автоматически весь длинный сценарий**.

Первая целевая область: Bybit USDT perpetual, весь фьючерсный портфель при запросах о риске и конфигурации, **Veles ИЛИ GinArea PRO**, только для **ручного применения**. Это текстовые артефакты `Markdown`, без собственных API-клиентов, сервера, фонового мониторинга, реальных ордеров и персональных аккаунтных данных в GitHub.

**Не обещать** загрузку Skills в ChatGPT автоматически. Каждый критичный workflow обязан явно сверить доступность/фактическое чтение инструкций `AGENTS.md` и выбранных `SKILL.md` из `feature/initial-agent-mvp` или честно работать в ограниченном fallback. **Открытые вопросы RV-02/RV-03/RV-04/RV-06**, ограничения TV-01–TV-04 и непроверенные реальные F/A/H/R в рамках FR-038 **остаются открытыми**: не обозначать их как закрытые и не выдавать реальный `READY` без доказательств.

## 3. Принцип сценария и формат минимального пользовательского промпта

Каждый пользовательский шаг состоит из **одной понятной команды**, необязательных контекстных слотов и следующего явного решения пользователя. Для простого R1-обзора достаточно пары и горизонта, а не аккаунтной T02. Для R2 в отсутствии обязательной OHLCV указать условность, отказаться от точных уровней. Для R3 обязательно требовать актуальный **полный T02/T03/T04 и Mark**, реальную выбранную **P02**, подтверждённый весь FR-risk и все F/A/H/R; право давать `READY` из одной формы/цены **не возникает**.

Выход каждого рабочего шага: `цель и режим; что подтверждено и источники/время; что рассчитано/предположено; основной результат; риски и границы; точечные запросы данных; следующий выбор пользователя`. Статусы `READY/NEEDS_DATA/UNVERIFIED/REJECTED` только там, где действительно есть решение о торговой конфигурации, иначе понятный предварительный анализ. `NOT_CHECKED` для отсутствующих H02/H03 — локальный факт, а известный H04 блокирует новый риск.

**Доступ к GitHub:** пользовательские промпты не должны притворяться, что умеют сами устанавливать/подключать Skills. Если необходимая GitHub-инструкция недоступна, раскрыть ограничение и по необходимости запросить конкретный файл, **не** утверждать чтение, если прочитан только README или старая память.
