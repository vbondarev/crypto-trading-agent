## 1. Область и границы

Сверены [FR-029/031/033/034](requirements.md), инварианты [I01–I14 (05.1)](risk-management.md#33-обязательные-инварианты-нормализации), объекты A01–A11 и T02/T03/T04, правила R3 из [data-freshness.md](data-freshness.md), описание account/position/order/risk-limit [Bybit V5](https://bybit-exchange.github.io/docs/v5/account/wallet-balance). Публичная Bybit-документация подтверждает **смысл названий полей**, не подключение приватного API и не универсальную математическую модель.

**Ключевые пределы испытаний:** нет подтверждённого реального метода для IM по всем вариантам UTA/Cross/Isolated/Portfolio, нет вычисленной биржевой ликвидации, upper bound Short и 4 стрессов. Числа `IM0=250`, `released=40`, `filled_positionIM=42`, `next_IM=38` — **синтетические допущения для проверки учётного перехода**, не вычисленные требования биржи. Сценарий `R_required=66` опирается на синтетические, заранее ограниченные ставки. Из положительного условного итога нельзя делать вывод о безопасности реальной сделки.

**26 эталонных сценариев** из [`5.4](risk-management.md#54-синтетическая-нормативная-матрица-e01e26) предусмотрены для будущего теста применения инструкций. Их наличие не превращает 26 кейсов в 26 исполненных прогонов модели. Непосредственные арифметические подмножества E01–E06, E09–E15, E18–E20, E23–E24 представлены в M01–M24; остальные — **смысловые правила со статусом NOT_EXECUTED_AS_LLM_TEST**.

Особенно важно: для E07–E08 **отсутствующие FX/account-mode данные** должны вести к `UNVERIFIED`, не к математике `notional/leverage`. Для E21 и E22 **неизвестный расход и предполагаемое исполнение Stop/OUT** не подтверждают резерв или максимальный убыток. Для E25–E26 **условные заявки** могут сформировать новую позицию даже если текущая зарезервированная IM не увеличилась.

## 4. Проверка границ статусов

- **PASS только отдельной проверки** 30%/5×/3 позиций/обеспечения означает `PASSED_FOR_SUBSET`, а не торговый `READY`.
- Доказанное нарушение одной из жёстких границ → `REJECTED` для увеличения риска независимо от пропусков в других ветвях; снижение риска по FR-039 допустимо.
- Недостающий обязательный T02, ставка или идентификатор → `NEEDS_DATA`; существенная непроверенная модель IM, валютная конверсия, либо конфликт → `UNVERIFIED`. Оба режима исключают `READY`.
- **FR-030, FR-032, FR-037, FR-038, FR-040** и все требования R3, действительная платформа P01/P02 остаются вне закрытия 05.2. TV-01–TV-04 и RV-02/RV-03 не закрывать.
